# Инварианты движка

## Scenario invariants — S2B-1, verified 2026-10-09

- Only explicit scenario configuration enables starting-island/bonus mechanics. All existing preset defaults and Base remain unchanged; no map-name dispatch or implicit +2 policy.
- Restricted accepted openings touch configured components and leave enough distance-rule capacity for the remaining snake order. Initial route commands retain ordinary anchored road/ship validation. Undersized configured regions reject before match creation.
- Setup islands become each player's recorded home islands only when bonus tracking is enabled. Setup never awards bonus VP. One accepted main settlement on a non-home island adds ordinary VP plus the configured bonus once per player/island; city upgrades/further settlements/opponent arrival do not reset or duplicate awards.
- Rejections preserve occupancy/resources/VP/ledger. PostgreSQL commit failure publishes no award and retains the old head/receipt state; replay/reconnect/recovery cannot duplicate an accepted award. Rematch resets history rather than carrying bonuses forward.
- Trusted v3 requires complete recorded history and valid public references; normal recovery never executes gameplay or reconciles VP. V1/v2 default to disabled scenario mechanics. Verified S1 provenance cannot acquire the new mechanics; unknown markers keep F2 gates and F1 private publication authorization.
- Public `special_vp` is a breakdown already included in total VP. Opponents' hidden VP/dev cards/resources remain private until the existing game_over score reveal. Only the active player can win; no new Base scoring/timing rule.

Evidence: **881 pytest with PostgreSQL / 253 web**, TypeScript/build, real Qt save/load and focused two-profile/two-client Chrome. Existing Largest Army tie handling is **known broken**, separately documented; the 348/508 scenario baseline remains unresolved. This verification is not a full natural-game/device/load certification. [[plans/seafarers-s2b-1]]

## Seafarers S1 — verified 2026-10-08

- Longest route uses a single edge trail, own-building transitions and opponent interruption, with one ≥5/2VP achievement. Tied qualified holders retain it; recomputation cannot double-award VP. Base counts roads only. Only the active player wins; entering their turn checks already earned VP before Roll.
- Ship construction/setup/movement, destination settlement and Gold commands validate before changing resources, occupancy, history or pending state. Direct hostile WS tests compare full GameState plus Room tick/dice/bag/events/timer, require a consumed rejected receipt and inert duplicate, then exercise a valid correction.
- Successful main construction records the original ship edge; one accepted move consumes the active-turn entitlement. Rejected movement does not consume it. End Turn resets both private flags without removing pieces. Reconnect, duplicate receipts and recovery cannot grant a second move.
- Private history survives codec v2; released v1 never invents missing ship age/movement. All restored main Seafarers turns conservatively lock moves until End, including pre-Roll free builds. Network projections omit private flags, seed/deck, opponent hands/cards and pending choices.
- Gold blocker applies to settlement/city production; second setup choice preserves anchor/index until a route is placed. Bank supply stays nonnegative, manual choices conserve cards and exhaustion resolves unfulfillable requests. Numeric recipient order is an implementation fact with scarcity-policy limits.

Historical S1 tests: 694 pytest including real PostgreSQL recovery/auth; 235 web; scenario baseline 348/508. Those checks cover that checkpoint's S1, not all map/scenario/desktop/device behavior. Latest verification is above. Evidence — [[plans/seafarers-s1]].

## Game UX 2.3 — verified 2026-10-06

- Discard threshold — approved configurable rule option, default 7, strict int 1..50. Roll 7 требует discard только при hand > threshold; формула floor(hand/2) не меняется. Boundary equal/above, invalid config, host/read-only/lock/rematch и offline round-trip проверены. Costs/production/dev effects/Seafarers rules не менялись.
- Gameplay feed добавляется только после accepted command. Private projection по recipient не раскрывает stolen type observer, foreign production resources, купленную dev card, private choices или seed. Rejected commands не создают event; historical events не исполняются как commands.
- Normal multiplayer по-прежнему не позволяет выдавать ресурсы/выбирать dice. Явное исключение только для Test Room на `CATAN_ENABLE_TEST_TOOLS=1`, current active host и ordinary ownership/sequence boundary. Named debug validations выполняются на копии; refused action сохраняет весь GameState и Room metadata. Bank transfer conservation проверена. Test tools — developer fixture capability, не обычное gameplay правило.
- Animation не меняет state/counter/entitlement. Direct dev click меняет лишь путь отправки прежней команды; paid/free-road/one-card/new-card validation прежняя. Road Building fix dcadcab сохранён.

32 новых cases — [test_playtest_feedback.py](../../tests/test_playtest_feedback.py); всего 266 pytest. Scenarios реально повторены: 348/508, восемь прежних failing scenarios по 20 запусков; ошибки Must roll before actions не исправлялись. Подробности network boundary — [[Сервер и протокол#Game UX 2.3 — personalized events and Test Mode]]. Исторические результаты ниже не заменяют эту проверку.

Источник: [[Спецификация пользователя]]. Инвариант — условие, которое должно оставаться верным после любого действия.

- Сервер/движок определяет результат; клиент только запрашивает действие.
- Клиент не может напрямую выдавать ресурсы.
- Клиент не выбирает кубики вне явно включённого debug/test-режима.
- Координаты существуют на текущем поле.
- Банк не содержит отрицательных количеств.
- Ошибочная команда не меняет состояние.
- Скрытая информация не попадает к неавторизованному получателю снимка.

До изменения состояния проверяются фаза, активный игрок при необходимости, владение, координаты, стоимость, наличие фигур, топология и ограничения сценария.

## Enforcement verified — 2026-10-02

Production Hardening Phase 1 проверяет конкретные границы:

- WS roll содержит только намерение; значение генерирует сервер. Debug-поля отвергаются даже при CATAN_DEBUG_ROLLS=1. Прямой deterministic engine API используется только trusted offline/tests.
- WS whitelist не содержит grant_resources. Trusted fixture helper сначала проверяет весь набор выдаваемых ресурсов.
- `_vertex`, `_edge`, `_tile` проверяют целочисленный тип (bool/float/string не ID), membership в текущей топологии и land/sea. can_place* тоже отсекают отсутствующие объекты. Settlement не ставится на sea-only vertex; road не накладывается на ship и не продолжается через чужую постройку. Включить setup после его завершения клиентским флагом нельзя.
- `play_dev` проверяет тип карты, возраст, лимит хода, pending и полный ресурсный эффект **до** pop/флага. Year of Plenty требует две карты, неотрицательные integer quantities, агрегирует одинаковые ресурсы и сравнивает суммарный запрос с банком. Monopoly работает с индексами игроков и совместим с Qt-моделью без player.pid.
- Invalid Road Building placement не расходует бесплатную дорогу. Отказ строительства/банкового или domestic обмена сохраняет ресурсы, банк, фигуры и trade offer. Неверная жертва проверяется до движения robber/pirate. Повтор discard отклоняется.
- Production и setup выдача ограничены остатком; choose_gold и bank trade проверяют полный запрос до mutation. Monopoly переносит руки и не затрагивает банк. Тесты проверяют неотрицательность и сохранение суммарного ресурса.
- Снимок зависит от pid; чужие res/dev_cards/hidden VP и приватные choices закрыты. Seed и точный bank тоже не передаются. Контракт — [[Сервер и протокол]].

Негативные regression-тесты сравнивают deepcopy **всего** GameState, а не только сериализованные поля: так проверяются dev_cards/deck, free_roads, flags, pending, offers и другие скрытые данные. Транспортный seq может продвинуться при отказе; он не является GameState, см. consumed-sequence контракт.

В исходной Phase 1 проверено 100 engine cases, 21 server/protocol cases и 3 desktop compatibility cases, дополнительно 7 web transport cases. Это доказательства для перечисленных путей, не формальное доказательство атомарности всех будущих команд или восстановления повреждённого состояния из save. Актуальные открытые расхождения перечислены в [[Project State]].

## Pirate lifecycle enforcement — 2026-10-02

- `move_pirate` требует enable_pirate, main phase, своего turn, pending `robber_move` и совпадающего pending_pid. Без события движение запрещено независимо от rolled.
- Pending разрешает выбор move_robber **или** move_pirate; discard сначала должен завершиться. Оба варианта расходуют одно событие. Успешный pirate очищает pending_action/pending_pid/pending_victims; повтор не может переместить другую фигуру или снова украсть карту.
- Sea hex, другая текущая клетка и допустимая ship-victim проверяются до mutation. При любом проверенном отказе deepcopy полного GameState равен состоянию после команды; событие остаётся доступным для исправленной команды.
- Кража встроена в move_pirate, отдельного этапа theft нет. Допускается максимум один ресурс за событие. Новое событие после завершённого действия снова разрешает выбор фигуры; прежний отказ или успех не создаёт нового события.

Проверки: 15 engine cases в [test_pirate_lifecycle.py](../../tests/test_pirate_lifecycle.py), 4 desktop offline/online handler cases в [test_pirate_ui.py](../../tests/test_pirate_ui.py), реальный WS success/duplicate/fresh replay case в [test_server_authority.py](../../tests/test_server_authority.py), 5 React render/click cases в [BoardView.test.mjs](../../web/tests/BoardView.test.mjs). Старые pirate coordinate/victim regressions получили pending fixture, чтобы проверять нужную валидацию, а не проходить из-за отсутствия trigger.

Полный pytest: 154 passed; web: 21 passed. Все 508 сценарных запусков сравнены до/после: 348 passed / 160 прежних отказов, с полностью совпадающими failure details. Browser DOM e2e и полная LAN-партия не проверялись.

## Board legal projection — verified 2026-10-05

- board_legal_moves получает pid адресата. Чужие affordability/free-build и private choices не попадают в его legal; вне своего хода обычные board targets пусты.
- Генерация legal не меняет живой GameState. Для семи board-команд прежний apply_cmd выполняется только на изолированных копиях, включая mutable resources/bank/occupancy/pending/flags. Шарится read-only geometry уже скопированной доски, не исходные объекты партии.
- Подсветка означает принятие соответствующей команды в этом состоянии. Исполнение всегда повторно валидирует текущий state; устаревший hint не даёт обхода cost/ownership/pending checks. Неуспешное действие сохраняет state и не создаёт optimistic piece в renderer.

26 cases в [test_board_legal.py](../../tests/test_board_legal.py) проверяют ограничения ресурсов/pieces/roll/setup/free roads/pending, personal privacy, full-state immutability, полные build/move lists против executor и явный victim choice. Это проверка текущих веток, не доказательство всех будущих rules changes; при изменении engine эти differential cases должны сохраняться. Gameplay rules Phase 2 не меняла.

## Road Building lifecycle — verified 2026-10-05

Дополнение 2026-10-06: server timer не очищает free_roads и не выбирает placement автоматически. Положительный credit блокирует timeout End; explicit End по-прежнему очищает остаток через прежний cleanup. Этот lifecycle regression suite остаётся зелёным.

- `play_dev(road_building)` даёт до двух бесплатных road placements в текущем ходу через собственный `free_roads[pid]`, без отдельного pending_action. Разрешённое существующим engine строительство до roll сохранено; каждая успешная бесплатная дорога уменьшает counter на один и не списывает ресурсы.
- Только успешный `apply_cmd(end_turn)` вызывает `end_turn_cleanup` и обнуляет остаток заканчивающего ход игрока до передачи turn. Уже построенные дороги сохраняются. Следующий собственный ход до/после roll не восстанавливает этот entitlement; обычная платная дорога требует wood + brick.
- Ошибочный road placement и отклонённый End Turn не меняют полный GameState и не расходуют остаток; исправленная команда может использовать его в том же ходу. В проверках сравнивается deepcopy всей партии, включая counter и occupancy.
- Персональный server snapshot после End Turn и на следующем собственном ходу содержит свой `free_roads` со значением 0 и `legal.road_free=false`; форма протокола и legal projection не менялись. Сброс работает в общем Python-движке, включая существующий server dispatch.

9 regression cases в [test_road_building_lifecycle.py](../../tests/test_road_building_lifecycle.py): 0/1/2 placements, реальный цикл двух игроков, сохранение дорог, paid/free отказ после истечения credit, invalid edge/occupied edge/non-boolean free, отказ End до roll и server commands/personal snapshots. До runtime fix четыре из этих cases воспроизводили баг; после — все проходят. Полный pytest: 195 passed. Все 508 сценарных запусков сравнены до/после: 348 passed / 160 прежних отказов `Must roll before actions`, без изменений outcomes/failure details; старые scenarios/assertions не исправлялись. Web/build/browser в этой узкой engine-задаче не повторялись.

## Room policy invariants — verified 2026-10-06

- Server chooses starting_pid; rotated snake и первый main согласованы. Цвет/клиент не определяют turn order.
- Только accepted Roll расходует private balanced_v1 bag и меняет public dice/count; rejected/duplicate/forged intents не расходуют outcome. Random не использует bag. Reconnect не меняет deadline/RNG/ownership.
- Settings whole patch/host/status и unique color проверяются до mutation. Config revision и request confirmation защищают pending UI от stale room_state; новая комната не наследует pending.
- Timer auto-actions проходят прежний executor. Server pending_action или free_roads блокирует авто-решение; никаких random victims/resources/targets. Due deadline action отделён от client rejection и не расходует client sequence.
- Hidden bank сохраняет прежний private contract; Visible — принятая пользователем публикация bank counts, не обещание защиты от two-player deductions. Private bag/deck/seed/foreign exact hands и active hidden VP остаются закрытыми в обоих modes. Историческое утверждение выше «точный bank не передаётся» теперь относится к Hidden.
- Чат server-owned/bounded/rate-limited/plain text; rejection не добавляет сообщение и не меняет rate state. Timer очищается при setup/Off/game_over/rematch/destroy/shutdown; Room не создаёт отдельный вечный task.

[test_room_ux.py](../../tests/test_room_ux.py): 31 regression cases, включая реальные WS двух клиентов, fake-clock expiry/grace/mandatory/lifecycle, full-bag weights и accepted-only consumption. Full pytest 234/234; web 119/119; 19 Chrome cases. Все scenarios до/после 348/508 с одинаковыми outcomes/failure details. Полное описание/limits — [[Сервер и протокол#Room policy — Game / Room UX 2.2]].
