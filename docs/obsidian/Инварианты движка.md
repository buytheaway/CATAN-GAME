## Public Fog beta authorization invariants

**Production policy implemented 2026-10-18; verification completed; results and limits in [[Project State]].** Only canonical two-player `seafarers_fog_beta_2` with durable `catan-fog-beta-1` can enter normal Fog gameplay. New admission is off by default; its switch is separate from emergency suspension of existing matches. Host/seat/session/controller ownership, authoritative shared rules, detached candidates, F1 private publication and COMMIT-before-ACK remain required. No client field or test capability can grant production access.

Pure recovery never generates assignments, replays rewards or recalculates VP/achievements. Pending Gold remains entitled-player-only, timers/Test Mode/Qt unsupported, unknown/internal legacy provenance closed. Historical paragraphs below stating that all public Fog is unavailable describe their old checkpoint; the narrow exception and rollback policy are [[Architecture Decisions#ADR-025 — Explicit custom Fog beta admission and emergency stop]]. Approved discovery/reward/turn rules are unchanged.

## Input rejection and persistence isolation — SEC-01

**Implemented/focused-tested 2026-10-12**, security validation only, no gameplay-rule change:

- Invalid client JSON/storage strings, guest names and supplied nested command types are rejected before dispatch. Malformed intents change neither GameState nor room config/tick/revisions/seq; a corrected intent can use the same unconsumed sequence.
- Development-card dispatch forwards only closed typed `dev_card_options`; untrusted fields cannot collide with engine parameters. Card ownership/maturity, turn, costs and effect atomicity remain shared-engine checks.
- Every parsed map-rule numeric alias/flag is validated before conversion/persistence. A controlled `RuleError`/`MapValidationError` is not a PostgreSQL outage and cannot disable unrelated rooms. Unexpected programming errors are not relabelled by the WS endpoint as durable failures.
- Genuine durable write/read failure still fences readiness/room, discards an uncommitted candidate and prevents successful ACK/publication. A valid-shaped gameplay refusal still commits its consumed sequence/rejected receipt under ADR-006. COMMIT uncertainty, recovery, F1/F2 and public Fog DISABLED are unchanged.

Before/after raw WS, cross-room isolation, real PostgreSQL connection refusal, unchanged state/head, receipt/reconnect and unexpected-error evidence — [test_security_input.py](../../tests/test_security_input.py). Latest full verification and remaining security scope — [[Project State]], [[Сервер и протокол#Client input isolation — SEC-01]].

## Theft and ordinary production — B1/B2

Implemented/focused-tested **2026-10-12**; intended rules are unchanged:

- Theft chooses a **card**, not a resource type or the largest pile. Probability is `quantity / total_cards`; exactly one card moves between thief/victim, stock and total cards per resource are conserved. Empty or rejected actions do not draw or transfer cards. Target/victim validation precedes mutation.
- Gameplay entropy is server-owned and independent of public map seed. `theft_rng` is an internal executor keyword only; multiplayer movement accepts only `type`, `tile`, optional `victim`/`victim_pid`. Resource/result/seed/RNG fields are rejected. Legal probes use copied state and their own RNG, not gameplay entropy.
- Ordinary production gathers **all** per-resource/player demands before distributing. Multi-recipient shortage awards zero of that resource; a sole recipient takes the remaining stock up to demand. Settlement=1/city=2, matching number and robber blocking apply before aggregation. Other resources are independent; iteration/key/codec/recovery order cannot choose a winner.
- Accepted candidate hands/events and receipt are committed before publication/ACK. Duplicate/reconnect/lost-ACK retries do not execute theft/production again. A transaction aborted before COMMIT keeps the previous hands and may draw afresh on a later unaccepted-intent retry; committed/ambiguously committed outcomes are recovered from durable state, never rerolled.
- Codec v4 and historical readers preserve recorded hands/results. Recovery does not apply corrected rules retrospectively. Existing verified provenance and F1/F2/Fog gates are unchanged.

Controlled-card-position, Sea Ring seed 17/wood=1/roll=2, historical-reader, PostgreSQL privacy/rollback/replay/recovery evidence — [test_resource_allocation.py](../../tests/test_resource_allocation.py), [test_resource_allocation_recovery.py](../../tests/test_resource_allocation_recovery.py). Full verification — [[Project State]].

- A valid hidden land/sea/token reassignment with identical known state cannot change projected snapshots/legal/metadata/events, equivalent invalid-command errors or recipient pending data before accepted discovery. Tests validate each alternative as a trusted v4 state; they never equate raw private snapshots with public data.
- Unknown tile projection contains only original index/geometry, hidden visibility, terrain fog and null number. Allowlisted scenario/metadata excludes pools/digest/ledger/continuation and hidden island/coast data; game_over and host status do not reveal it.
- Legal projection reuses the known-terrain executor on independent copies. It cannot mutate live discovery/history/bank or invoke a second UI rule engine. Unauthorized/invalid routes/choices remain rejected without state changes.
- Committed discovery events name only already-revealed tiles and public reward facts; Gold resource choice and hands remain audience-private. Frontend/rendering was public-fixture-tested in .3A; .3B also verifies the real scoped WS publisher/ownership/recovery and Chrome consumers. Only explicit in-process room/match capability permits internal transport; normal startup/recovery/client input cannot activate it. Public Fog remains disabled. Renderer guards/animations cannot replace server authorization or execute rewards/rules. [[Сервер и протокол#Internal Fog live transport — S2B-2B.3B]].

## Trusted fog foundation invariants — S2B-2B.1

Foundation constraints below remain; **S2B-2B.2A implemented/tested 2026-10-12** adds internal execution:

- Only explicit in-process trusted engine/probe/commit keywords opt in; client fields, current marker alone and an open socket cannot enable public fog. Every public selection/start/command/legal/serializer/debug/Qt/timer gate stays active.
- Only accepted road/ship/setup/free construction and move destination reveal. Both endpoints' vertex adjacency is considered; newly hidden IDs reveal in ascending order once. Rejections/settlements/cities/roll/probes/source removal preserve visibility and rewards.
- Unknown is neither known land nor sea and cannot affect placement, production, initial grants, figure targets or initial coasts/ports. Revealing never modifies actual terrain/token assignments or graph/IDs/ports.
- Standard reward is one available matching card; Sea/Desert none. Bank shortages mark unavailable without debt, placement cancellation or future replay. Gold uses existing entitled-player choices; every processed tile keeps a durable single-use ledger entry.
- Pending discovery Gold blocks unrelated actions and keeps setup index/anchor/turn. Valid choices consume recorded entries in order; invalid choices change nothing. Empty-bank completion marks remaining entries unavailable. Setup and own-turn victory resume exactly once; Road Building and ship lifecycle counters remain consumed correctly.
- Native-current internal persistence keeps the same candidate, lock, PostgreSQL COMMIT, receipt and uncertainty fences. Unknown marker/epoch/lifecycle/finished-state changes cannot opt in. No waiting transaction, recovery rule/RNG/reward execution or historical score repair.
- Fog legal probes share no mutable board/history/bank/continuation with live state or another probe. At .2A projection was planned; .2B adds pure internal safe projection above and .3A adds fixture-tested rendering. Public execution/publication remains disabled; full suite and scenario evidence — [[plans/seafarers-fog]].

**Historical foundation scope (2026-10-09):** the following bullets describe what S2B-2B.1 enforced before the internal executor above existed.

- Only explicit recipe v2/profile enables internal fog; existing preset behavior remains fog-disabled. Actual assignments live in one BoardState with original IDs, independently randomized from public seed.
- Revealed IDs are a subset of initial hidden IDs. Every revealed tile has one typed reward record; duplicate/missing records, changed completed rewards and discovery rollback reject. Pending Gold/continuation references must be internally consistent; this stage does not execute or award them.
- Assignment digest is validated at trusted encode/decode; same-match transition checks prevent changing assignments even with a replacement digest, changing initial mask/geometry/ports or hiding already revealed tiles. Domain records are frozen; this is not a global immutable Tile refactor.
- Initial setup and ports use known territory; raw hidden contents cannot influence opening capacity or port placement. Fog plus starting_islands/positive island VP is unsupported.
- Codec v4/3 round-trip restores recorded contents/history/continuation without RNG, rules, VP/achievement/reward recalculation or automatic revelation. Historical nested v1/v2/v3 schemas restore fog-disabled state without conversion.
- Public creation/start/execution/legal/projection/debug/Qt paths remain disabled, even after game_over/reconnect/rematch. Current marker alone cannot activate fog. Ownership stays required; restricted ownership-only writes cannot advance or prune a trusted head.

Evidence and verification limits — [[plans/seafarers-fog]]. Exploration triggers, production/rewards, known-terrain legal probes, safe playable projection and rendering are **planned S2B-2B.2**, not enforced playable mechanics in this foundation.

## Largest Army invariants — focused fix, 2026-10-09

- No award below three played Knights. A qualified holder remains owner on two/three-way ties; a unique challenger must strictly exceed it to take the award. A tie without a holder does not choose one arbitrarily.
- Retention/growth/repeated calculation never adds another 2 VP. Transfer removes exactly 2 from the previous holder and adds exactly 2 to the new holder. Rejected Knight commands preserve cards/counts/VP/achievement.
- `check_win` remains current-player-only, including before Roll; an opponent's tying Knight cannot erase the waiting holder's award or declare an off-turn winner.
- Normal v1/v2/v3 decoding and PostgreSQL recovery preserve recorded achievements/VP, including old unawarded/stale values; no gameplay calculation, historical repair or new ruleset classification. Scenario home/award ledger is unaffected.

Targeted engine/codec/PG verification: [[Project State#Largest Army tie handling — focused correctness fix]]. ## Seafarers S1 — verified 2026-10-08

- Longest route uses a single edge trail, own-building transitions and opponent interruption, with one ≥5/2VP achievement. Tied qualified holders retain it; recomputation cannot double-award VP. Base counts roads only. Only the active player wins; entering their turn checks already earned VP before Roll.

## Game UX 2.3 — verified 2026-10-06

- Discard threshold — approved configurable rule option, default 7, strict int 1..50. Roll 7 требует discard только при hand > threshold; формула floor(hand/2) не меняется. Boundary equal/above, invalid config, host/read-only/lock/rematch и offline round-trip проверены. Costs/production/dev effects/Seafarers rules не менялись.

Test tools — developer fixture capability, не обычное gameplay правило.
- Animation не меняет state/counter/entitlement. Direct dev click меняет лишь путь отправки прежней команды; paid/free-road/one-card/new-card validation прежняя. Road Building fix dcadcab сохранён.

Источник: [[Спецификация пользователя]]. Инвариант — условие, которое должно оставаться верным после любого действия.

- Сервер/движок определяет результат; клиент только запрашивает действие.
- Клиент не может напрямую выдавать ресурсы.
- Клиент не выбирает кубики вне явно включённого debug/test-режима.
- Координаты существуют на текущем поле.
- Банк не содержит отрицательных количеств.
- Ошибочная команда не меняет состояние.
- Скрытая информация не попадает к неавторизованному получателю снимка.

## Enforcement verified — 2026-10-02

Production Hardening Phase 1 проверяет конкретные границы:

- WS roll содержит только намерение; значение генерирует сервер. Debug-поля отвергаются даже при CATAN_DEBUG_ROLLS=1. Прямой deterministic engine API используется только trusted offline/tests.
- WS whitelist не содержит grant_resources. Trusted fixture helper сначала проверяет весь набор выдаваемых ресурсов.
- `_vertex`, `_edge`, `_tile` проверяют целочисленный тип (bool/float/string не ID), membership в текущей топологии и land/sea. can_place* тоже отсекают отсутствующие объекты. Settlement не ставится на sea-only vertex; road не накладывается на ship и не продолжается через чужую постройку. Включить setup после его завершения клиентским флагом нельзя.
- `play_dev` проверяет тип карты, возраст, лимит хода, pending и полный ресурсный эффект **до** pop/флага. Year of Plenty требует две карты, неотрицательные integer quantities, агрегирует одинаковые ресурсы и сравнивает суммарный запрос с банком. Monopoly работает с индексами игроков и совместим с Qt-моделью без player.pid.
- Invalid Road Building placement не расходует бесплатную дорогу. Отказ строительства/банкового или domestic обмена сохраняет ресурсы, банк, фигуры и trade offer. Неверная жертва проверяется до движения robber/pirate. Повтор discard отклоняется.
- Production и setup выдача ограничены остатком; choose_gold и bank trade проверяют полный запрос до mutation. Monopoly переносит руки и не затрагивает банк. Тесты проверяют неотрицательность и сохранение суммарного ресурса.
- Снимок зависит от pid; чужие res/dev_cards/hidden VP и приватные choices закрыты. Seed и точный bank тоже не передаются. Контракт — [[Сервер и протокол]].

Негативные regression-тесты сравнивают deepcopy **всего** GameState, а не только сериализованные поля: так проверяются dev_cards/deck, free_roads, flags, pending, offers и другие скрытые данные. Транспортный seq может продвинуться при отказе; он не является GameState, см. consumed-sequence контракт.

В исходной Phase 1 проверено 100 engine cases, 21 server/protocol cases и 3 desktop compatibility cases, дополнительно 7 web transport cases. Это доказательства для перечисленных путей, не формальное доказательство атомарности всех будущих команд или восстановления повреждённого состояния из save. Актуальные открытые расхождения перечислены в [[Project State]].

## Pirate lifecycle enforcement — 2026-10-02

- `move_pirate` требует enable_pirate, main phase, своего turn, pending `robber_move` и совпадающего pending_pid. Без события движение запрещено независимо от rolled.
- Pending разрешает выбор move_robber **или** move_pirate; discard сначала должен завершиться. Оба варианта расходуют одно событие. Успешный pirate очищает pending_action/pending_pid/pending_victims; повтор не может переместить другую фигуру или снова украсть карту.
- Sea hex, другая текущая клетка и допустимая ship-victim проверяются до mutation. При любом проверенном отказе deepcopy полного GameState равен состоянию после команды; событие остаётся доступным для исправленной команды.
- Кража встроена в move_pirate, отдельного этапа theft нет. Допускается максимум один ресурс за событие. Новое событие после завершённого действия снова разрешает выбор фигуры; прежний отказ или успех не создаёт нового события.

Проверки: 15 engine cases в [test_pirate_lifecycle.py](../../tests/test_pirate_lifecycle.py), 4 desktop offline/online handler cases в [test_pirate_ui.py](../../tests/test_pirate_ui.py), реальный WS success/duplicate/fresh replay case в [test_server_authority.py](../../tests/test_server_authority.py), 5 React render/click cases в [BoardView.test.mjs](../../web/tests/BoardView.test.mjs). Старые pirate coordinate/victim regressions получили pending fixture, чтобы проверять нужную валидацию, а не проходить из-за отсутствия trigger.

Полный pytest: 154 passed; web: 21 passed. Все 508 сценарных запусков сравнены до/после: 348 passed / 160 прежних отказов, с полностью совпадающими failure details. Browser DOM e2e и полная LAN-партия не проверялись.

## Board legal projection — verified 2026-10-05

- board_legal_moves получает pid адресата. Чужие affordability/free-build и private choices не попадают в его legal; вне своего хода обычные board targets пусты.
- Генерация legal не меняет живой GameState. Для семи board-команд прежний apply_cmd выполняется только на изолированных копиях, включая mutable resources/bank/occupancy/pending/flags. Шарится read-only geometry уже скопированной доски, не исходные объекты партии.
- Подсветка означает принятие соответствующей команды в этом состоянии. Исполнение всегда повторно валидирует текущий state; устаревший hint не даёт обхода cost/ownership/pending checks. Неуспешное действие сохраняет state и не создаёт optimistic piece в renderer.

26 cases в [test_board_legal.py](../../tests/test_board_legal.py) проверяют ограничения ресурсов/pieces/roll/setup/free roads/pending, personal privacy, full-state immutability, полные build/move lists против executor и явный victim choice. Это проверка текущих веток, не доказательство всех будущих rules changes; при изменении engine эти differential cases должны сохраняться. Gameplay rules Phase 2 не меняла.

## Road Building lifecycle — verified 2026-10-05

Дополнение 2026-10-06: server timer не очищает free_roads и не выбирает placement автоматически. Положительный credit блокирует timeout End; explicit End по-прежнему очищает остаток через прежний cleanup. Этот lifecycle regression suite остаётся зелёным.

- `play_dev(road_building)` даёт до двух бесплатных road placements в текущем ходу через собственный `free_roads[pid]`, без отдельного pending_action. Разрешённое существующим engine строительство до roll сохранено; каждая успешная бесплатная дорога уменьшает counter на один и не списывает ресурсы.
- Только успешный `apply_cmd(end_turn)` вызывает `end_turn_cleanup` и обнуляет остаток заканчивающего ход игрока до передачи turn. Уже построенные дороги сохраняются. Следующий собственный ход до/после roll не восстанавливает этот entitlement; обычная платная дорога требует wood + brick.
- Ошибочный road placement и отклонённый End Turn не меняют полный GameState и не расходуют остаток; исправленная команда может использовать его в том же ходу. В проверках сравнивается deepcopy всей партии, включая counter и occupancy.
- Персональный server snapshot после End Turn и на следующем собственном ходу содержит свой `free_roads` со значением 0 и `legal.road_free=false`; форма протокола и legal projection не менялись. Сброс работает в общем Python-движке, включая существующий server dispatch.

До runtime fix четыре из этих cases воспроизводили баг; после — все проходят. Полный pytest: 195 passed. Web/build/browser в этой узкой engine-задаче не повторялись.

## Room policy invariants — verified 2026-10-06

- Server chooses starting_pid; rotated snake и первый main согласованы. Цвет/клиент не определяют turn order.
- Только accepted Roll расходует private balanced_v1 bag и меняет public dice/count; rejected/duplicate/forged intents не расходуют outcome. Random не использует bag. Reconnect не меняет deadline/RNG/ownership.
- Settings whole patch/host/status и unique color проверяются до mutation. Config revision и request confirmation защищают pending UI от stale room_state; новая комната не наследует pending.
- Timer auto-actions проходят прежний executor. Server pending_action или free_roads блокирует авто-решение; никаких random victims/resources/targets. Due deadline action отделён от client rejection и не расходует client sequence.
- Hidden bank сохраняет прежний private contract; Visible — принятая пользователем публикация bank counts, не обещание защиты от two-player deductions. Private bag/deck/seed/foreign exact hands и active hidden VP остаются закрытыми в обоих modes. Историческое утверждение выше «точный bank не передаётся» теперь относится к Hidden.
- Чат server-owned/bounded/rate-limited/plain text; rejection не добавляет сообщение и не меняет rate state. Timer очищается при setup/Off/game_over/rematch/destroy/shutdown; Room не создаёт отдельный вечный task.
