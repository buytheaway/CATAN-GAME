## Official The Four Islands — S3B

**Implemented, source/diagrams verified 2026-10-16.** Primary source: [Fifth Edition 2021 rulebook, printed pp.11–13](https://www.catan.com/sites/default/files/2021-06/catan-seafarers_2021_rule_book_201201.pdf). Page 11 defines setup/personal island awards; p.12 has the 3-player board, 13 VP ending and optional variable setup; p.13 has the distinct 4-player board. Both full diagrams and detailed harbor coast edges were visually inspected before implementation.

Canonical [3-player JSON](../../app/assets/maps/seafarers_official_four_islands_3.json) / [4-player JSON](../../app/assets/maps/seafarers_official_four_islands_4.json) reproduce fixed terrain, tokens and harbor edges. Loose inventories: 3-player = 15 sea + four each fields/forest/pasture/hills/mountains; 4-player = 12 sea + five each fields/forest/pasture + four hills/mountains. No Gold/desert. Number counts: 3-player `{2:1,3:2,4:2,5:3,6:2,8:2,9:3,10:2,11:2,12:1}`; 4-player `{2:1,3:2,4:3,5:3,6:2,8:2,9:3,10:3,11:3,12:1}`. Independent source columns and harbor corner anchors are transcribed in [layout/rule tests](../../tests/test_official_four_islands.py), not generated from the production recipes.

Existing pointy axial convention applies the same 90° clockwise transcription as S3A: source column `c=0..6`, downward half-row `k`, `r=c-3`, `q=3-(k+c-1)/2`. Original indices are column-major. Both variants append actual printed full sea positions `(2,0)` and `(-4,0)` at indices 35/36; `component_hex_count` / `frame_tiles` distinguish inventory from frame spaces. Canonical `sea_frame:true` reuses the inner-frame shipping policy, without a generated ocean halo or new IDs.

Each has nine exact coastal, endpoint-disjoint harbor edges: four generic 3:1 and five specialized 2:1 types, shuffled only among those anchors using existing map RNG. Terrain/numbers do not change with seed. General pp.3/7 harbor shuffle is distinct from the unimplemented optional variable terrain/number setup. Three-player robber is pasture 12, index 0; pirate is central sea index 17. Four-player robber is fields 12, index 29; pirate is bottom frame sea index 36. These differ from New Shores; no setup figures are inferred from that scenario.

Setup may use any legal land vertex; each player's one/two actual opening islands are durable homes. Existing scenario ledger grants +2 only for the first own main-phase settlement on each foreign island, even if another player started/settled there. Maximum special VP is 6/4 for one/two homes; city upgrades and command retries do not repeat awards. Shared own-turn victory target is 13; exact count and 13/7 settings are enforced at authoritative start/rematch/settings. Existing ship movement, resource/supply checks and route calculations are unchanged. [[Правила Seafarers#Official Scenario 2 — The Four Islands]].

Official selection/build requires the entire canonical recipe; modified/custom uploads cannot impersonate official identity or opt into frame semantics. New matches use `catan-seafarers-s3b-four-islands`, not the S3A marker. Writer v4/compatibility 3 and pure materialized recovery remain unchanged; no historical state is regenerated. [[Architecture Decisions#ADR-024 — Canonical Four Islands using the existing personal island ledger]], [[Состояние игры#Official scenario persistence — S3B]], [[Сервер и протокол#Official scenario admission — S3B]].

Evidence: [server/projection tests](../../tests/test_official_four_islands_server.py), [PostgreSQL recovery/receipt/privacy tests](../../tests/test_official_four_islands_recovery.py), [grant-free TCP full matches](../../tests/test_official_four_islands_natural.py). Three-player completion: 55 rolls/174 accepted actions, 13–2–3; four-player: 69/232, 13–2–4. The 140 Roll refusals and 20 missing-edge refusals are correct engine behavior for those old fixtures, not 160 engine bugs or regressions from Full-Match Validation. Pirate's masked later errors also included movement without a Seven/Knight event and an arbitrary non-adjacent sea fallback. No independently reproduced production defect was found.

[GameDriver](../../tests/harness/engine.py) adds explicit `begin_turn`, `finish_turn`, `advance_to`, `resolve_pending`, `ensure_resources`, `buy_dev_cards` and `reject`. They issue ordinary `apply_cmd` operations; no automatic bypass is inserted into `do`. Funding uses production and accepted maritime/domestic trades, preserving prices/bank totals. Cards come from the untouched seed-shuffled deck and mature across actual turns. Roll totals are controlled logged inputs to the trusted offline engine, not a client/server override. Production-choice probes run the executor on deep copies; accepted execution remains the sole authority. Bounds fail with fixture diagnostics rather than hanging or declaring success. [Utilities](../../tests/scenarios/utils.py) complete actual snake setup/Gold choices and choose available unblocked coastal anchors using the materialized graph; IDs, maps and inventory are unchanged.

Assertions retain card effects/minimums/costs and add exact failure reasons plus whole-state atomicity. Army checker preserves a qualified tied incumbent; no-holder ties remain unawarded. Army and road scenarios assert exact ±2 VP transfers; the graph road fixture checks an interior blocker and exact strict length reduction. The previously passing bank-shortage test now legally empties ore into a sole producer and funds the maritime payment before asserting **`Bank has not enough resources`**, rather than passing on **`Must roll before actions`**. Robber's production test uses the next actual turn and counts all unblocked matching yields with independent-resource/multiple-recipient/sole-recipient shortage handling. Existing dedicated B1/B2 tests retain cities/settlements, ordering/codec/PG and controlled theft coverage.

Reproducibility: map/deck seed is unchanged; default dice use `GameDriver.rng`, while action selection is deterministic from the materialized board/state. Theft uses a separate in-process `Random(seed ^ 0xCA7A)` injection. Production secure RNG and public protocol remain unchanged. The historical Qt smoke scopes its module RNG to `Random(seed)` and restores it after each test; its board was previously generated from unrelated random state. Reports retain scenario/seed, exact commands, outcomes (including intentional refusal), error details/trace and nonzero failure status. Run `.venv/Scripts/python.exe -B -m tests.run_all --reports-dir .venv/test-artifacts/harness-report` to preserve the tracked historical BUG_REPORT and place current reports in ignored artifacts. No `.env`, credentials or real user data are needed.

Verification: **649 relevant Python/isolated-PostgreSQL tests passed** including the initial 41 harness cases and existing natural Base/New Shores completion/recovery/rematch and official 3/4/custom map/rules/compatibility/privacy tests. The final **42-case focused suite** was repeated after adding the safeguard against treating engine exceptions as expected refusals. All ten repaired command-only fixtures ×20 seeds were separately replayed from pristine setup: **200/200, 20,371 commands, 20,153 accepted +218 expected refusals**, per-command resource/achievement/VP checks, rejection atomicity and exact final GameState equality. Existing 348 passing matrix cases still pass. Full pytest/frontend/assets/build/browser were not rerun because no runtime/frontend changed; older counts remain dated in [[Project State]].

Limits: the entire matrix is not 508 naturally played games. Historical graph/VP/secondary-robber fixtures deliberately construct isolated states, and Qt bot stability retains synthetic turn resets as controller smoke. They are not newly used to bypass rules in the repaired command-only fixtures. `scenario_seafarers_extra_presets.py` exports a helper without `run(driver)` and remains outside the original 508; four custom presets and official New Shores are checked separately by pytest. Broader conversion/registry expansion, arbitrary seeds and balance are future scope. Public Fog stays **DISABLED**; maps/provenance/codec/recovery/security and user data/preferences are untouched.

Two full sea outlines printed on the physical frame are appended after the component tiles: top `(2,0)`, bottom `(-4,0)` / `(-5,0)` for 3/4 players. `component_hex_count` and `frame_tiles` in the canonical recipe distinguish these spaces from loose inventory; they are not new trusted GameState fields or a generated ocean halo.

Harbor anchors are the exact diagram edges. Three players use eight anchors with three generic 3:1 and five resource-specific 2:1 types; four use nine anchors with four generic and five specialized. `ports_shuffle:true` shuffles only these type decks at fixed anchors using the existing map RNG. The 3-player diagram illustrates resource labels; the implementation does not claim that illustration forbids the general type shuffle. Variable terrain/number setup from pp. 8–9 is **not implemented**. Graph endpoints are coastal and disjoint; no auto-port approximation is used.

Both openings must be on the main island, identified by the existing stable component ID `0`. The shared setup/capacity checks and anchored Road/Ship choice apply. A player's first main-phase settlement on each smaller island gives +2 special VP plus the ordinary settlement VP, regardless of other players. Repeated settlements, city upgrades and replayed commands cannot repeat an award. Target is 14 VP on that player's own turn; discard threshold is 7. Both pirate and robber are enabled, with ordinary Seafarers ship/Gold/Knight rules and fully visible terrain.

The 3-player robber starts on hills 12 at `(-1,3)`; the 4-player robber starts on desert `(0,-1)`. The pirate starts on the bottom printed frame sea tile. Page 8 mistakenly names the pirate for the 3-player hills start; this is treated as a typo because the p. 9 diagram shows the robber there and pirate rules require sea. [Official frame FAQ](https://www.catan.com/faq/seafarers) permits inner frame shipping and forbids outer frame edges. Canonical-only `rules.sea_frame:true` recognizes existing boundary graph edges as inner sea frame; it does not add arbitrary outer routes.

`maps.official_preset_meta` authenticates exact shipped recipes and typed edition/player identity at creation; a client ID/name/marker is not proof of official status. Modified official uploads, frame opt-in on ordinary custom maps, wrong player count and target/discard changes are rejected. Start/rematch count actual connected seats and require the selected exact variant. Official selection resets inherited target override/discard settings to the official values; rematch starts a fresh ledger. Native matches receive `catan-seafarers-s3a-new-shores`, separate from unchanged Base/custom provenance; no saved match is rebuilt from these files during recovery. ## Trusted fog recipe — S2B-2B.1

Implemented **2026-10-09**, public selection/start **DISABLED**. Existing 12 presets/JSON remain map format v1 and fog-disabled. Independent recipe v2 is accepted only by the trusted builder/internal fixtures; it does not add a playable preset or map editor. Profile semantics and remaining work — [[plans/seafarers-fog]].

Recipe fields:

- `version: 2`, public tile order/`q,r`, visible actual terrain/number and hidden slots `{q,r,terrain:"fog",number:null}`.
- `fog_pool: {terrain:[...], numbers:[...]}` consumes exactly one terrain per hidden slot and one token per producing assignment; sea/desert receive no number. Duplicate terrain/token values are ordinary pool multiplicities.
- `rules.enable_seafarers:true`, `rules.scenario.fog:{profile:"shared-preassigned-v1"}`; Gold requires `enable_gold:true`. Fog rejects `starting_islands` and positive `new_island_vp`.
- Optional existing `ports`/`ports_auto`, visible initial robber/pirate. Unknown recipe/tile fields, private seed/full hidden layout, malformed positions, unsupported terrain/tokens and surplus/missing pool entries reject before assignment.

`maps._materialize_tiles` shuffles both pools with independent `random.SystemRandom()`; the ordinary `build_game(seed, ...)` seed does not reproduce hidden assignments. Keyword-only `fog_rng` injection makes trusted tests deterministic, without accepting a network RNG/seed. Actual Tile values are written once into the existing BoardState; indices and generated graph IDs remain unchanged. Recovery reads the materialized snapshot, never the recipe to assign again.

Unknown is neither known land nor known sea. Initial coasts/ports and figure positions cannot depend on actual hidden assignments; an authored port touching a hidden slot rejects. S2B-2B.2A `known_land_tiles` uses initial visibility plus recorded revelations for the existing setup/capacity guard; hidden contents never supply capacity. Accepted route discovery uses both endpoint vertex-adjacency and edge-adjacency, preserves original IDs/assignments and never regenerates topology or ports. This internal engine/reward lifecycle is implemented/tested 2026-10-12; public serializers/Qt still reject, and playable SVG/Board3D fog support remains planned.

Validation/recovery/gate evidence — [test_fog_foundation.py](../../tests/test_fog_foundation.py), [test_fog_feature_gate.py](../../tests/test_fog_feature_gate.py), [test_fog_recovery.py](../../tests/test_fog_recovery.py). Trusted format/markers — [[Состояние игры#Trusted fog persistence — S2B-2B.1]]. Existing scenario baseline below is historical; no harness expectations were changed.

S2B-2B.2B **implemented/tested 2026-10-12** adds only pure internal safe tile/metadata projections: unknown actual terrain/number masked, original geometry/IDs retained, no private pools/digest/ledger/island/coast derivation. Ports remain the stored initially visible-territory ports; no hidden shoreline data or new port placement is computed. Recipe/builder/presets/topology/rules are unchanged; public selection/start/commands/publication and SVG/Board3D Fog remain disabled. Valid trusted counterfactual land/sea/token assignments produce equal pre-discovery observations; evidence — [[Состояние игры#Fog player projection — S2B-2B.2B]], [[plans/seafarers-fog]]. Latest scenario rerun .2B is **348/508**, same 140 pre-Roll and 20 pirate fixture failures; no harness repair.


Setup/cities/repeated settlements do not receive it; opponents have independent awards. Target uses the existing `rules.target_vp` / room override. Gold is resource production, not a scenario VP award; fog/discovery is not implemented. Saved boards/history never regenerate from edited map files.

## Модель: определение карты и игровое состояние

**Map JSON** задаёт список клеток, а не готовые вершины/рёбра. **BoardState** содержит материализованные Tile, граф и размещённые фигуры. **GameState** добавляет игроков, ход, правила, pending, достижения и другие данные партии.

Реальный фрагмент [community_balanced_a.json](../../app/assets/maps/community_balanced_a.json), первые две клетки:

```json
[
  {"q": 0, "r": -2, "terrain": "fields", "number": 6},
  {"q": 1, "r": -2, "terrain": "forest", "number": 11}
]
```

В [base_standard.json](../../app/assets/maps/base_standard.json) те же позиции содержат `terrain: "random"`, `number: "random"`; terrain_deck/number_deck определяют состав.

### Координаты и IDs

- `q,r` — axial-координаты pointy-top гекса. Центр: `x = size * sqrt(3) * (q + r/2)`, `y = size * 1.5 * r`.
- Tile не имеет отдельного id-поля: **tile ID = индекс в массиве tiles**. Именно индекс используют adjacency, robber_tile/pirate_tile и команды `tile`.
- build_graph_from_tiles обходит тайлы в порядке JSON, вычисляет шесть углов (30 + 60*i градусов), объединяет совпадающие углы по quant_key с шагом 0.5 и выдаёт последовательные **vertex IDs**.
- **Edge ID = упорядоченная пара vertex IDs** `(min(a,b), max(a,b))`, а не самостоятельный номер. В JSON snapshot ключ — строка `"a,b"`, список edges — пары `[a,b]`.
- vertex_adj_hexes связывает вершину с индексами тайлов; edge_adj_hexes — ребро с индексами тайлов. Соседство тайлов можно получить по общему ребру, но отдельной таблицы tile_neighbors нет.
- Перестановка tiles в JSON меняет tile/vertex IDs. Они стабильны для одинаковых порядка координат и size; renderer не должен пересобирать/перенумеровывать граф.
- JSON `size` не выбирает engine size автоматически: build_game получает size отдельным аргументом; сервер использует 58.0.

Base и Coastal Lanes имеют 19 координат; Sea Ring/Gold Haven/Pirate Lanes — 37. Sea остаётся гексом того же графа, а не дырой. Никаких hardcoded 19 позиций у renderer нет. Island ID выводится как минимальный исходный tile index edge-connected land component; стабильность относится к конкретному сохранённому board, а не к разным definitions с переставленными tiles. Sea в island_ids не входит.

### Местность, номера, фигуры, порты

| Данные | Представление |
| --- | --- |
| Terrain | Tile.terrain: forest/hills/pasture/fields/mountains/desert/sea/gold; random существует только до материализации |
| Number token | Tile.number: integer или None; q/r/center/terrain/number отправляются в snapshot |
| Обычный ресурс | TERRAIN_TO_RES: forest→wood, hills→brick, pasture→sheep, fields→wheat, mountains→ore |
| Desert | Сухопутный тайл без обычного производства; обычный старт разбойника |
| Sea | Не производит стандартный ресурс; влияет на допустимость поселений/дорог/кораблей и пирата |
| Gold | Сухопутный тайл с номером; при enable_gold создаёт выбор обычного ресурса, не шестой ресурс |
| Поселение/город | occupied_v[vid] = (pid, level), level 1/2 |
| Дорога/корабль | occupied_e[edge] = pid / occupied_ships[edge] = pid |
| Разбойники/пират | robber_tile, robbers — tile indices, в Seafarers также -1 (initial offboard); pirate_tile — sea index или None |
| Port | BoardState.ports = [((a,b), "3:1" или "2:1:wood" и т. п.)]; snapshot: [[[a,b], kind], ...] |

Port связан с двумя вершинами ребра. Торговый доступ определяется своей постройкой на одной из них. Видимый морской фон Base не означает наличие sea tiles: в Base их ноль. Island IDs теперь derived topology helper, не новое поле GameState/snapshot. Fog/unknown, special scenario tokens, стартовые зоны и exploration rewards отдельной модели пока не имеют.

## Что действительно рандомизируется

### Terrain

_materialize_tiles перемешивает terrain_deck через переданный RNG, затем по одному выдаёт значения только клеткам `terrain="random"`. Фиксированные клетки не трогает.

Все восемь поддерживаемых terrain могут находиться в пользовательской колоде, включая sea/gold/desert. Это выбор типа на **существующей координате**, не генерация новых координат или островов. В поставляемых Seafarers sea/gold заданы фиксированно; остальные выбранные позиции перемешиваются.

Если случайных клеток меньше колоды, loader всё ещё использует только её начало для custom JSON. В обновлённых четырёх Seafarers decks имеют точное число random slots; presence/count всех ресурсов/desert больше не зависит от усечения колоды. **Historical S1:** simple_1/simple_2 выдавали 19-card deck в 13/9 slots, Pirate Lanes тоже усекал deck. Исправление фиксирует quotas, но не доказывает probability balance.

### Number tokens

Аналогичный shuffle number_deck. У random-number клетки, материализованной как desert/sea, number становится None и карта из number_deck не расходуется. Gold может получить номер.

Есть seed-based shuffle. Нет алгоритма перестановки с запретом соседних 6/8, проверки соседства сильных чисел, локальной суммы probability weights или баланса ресурсов/стартовых вершин. Стандартная number_deck задаёт состав, но не проверяет размещение. В Base Standard при seed=1 обнаружены две пары соседних 6/8; в high_prob — шесть. community_balanced_a/b/c имеют ноль таких пар благодаря фиксированным данным.

### Ports

Явный `ports` используется без shuffle; даже `ports: []` отключает автопорты. Иначе _auto_ports:

1. Берёт `coastal_edges`: ровно один land tile, с другой стороны sea либо внешняя рамка.
2. Сортирует по углу середины ребра относительно (0,0).
3. Пробует примерно равномерные позиции, затем добирает из того же порядка; исключает общие vertex endpoints. Число ограничено count, deck и доступной береговой геометрией.
4. Перемешивает типы из deck и сопоставляет выбранным рёбрам.

**Auto positions при одинаковых terrain/геометрии/count не случайны; случайны типы.** Берег может смотреть внутрь архипелага. Исходные 12 Base/custom presets имеют девять портов: четыре 3:1 и по одному специализированному 2:1 для каждого ресурса. На маленьком custom coast auto может выдать меньше requested count. Authored ports сохраняют порядок/edge/kind, кроме явного `ports_shuffle:true`, которое перемешивает только существующий type deck на неизменных anchors (S3A). При новом build проверяются существование ребра, настоящий берег и отсутствие общих endpoints. `ports: []` сохраняет отсутствие портов.

**Historical bug — до S2A, seed=1:** auto выбирал внешнюю границу всей сетки без land/sea проверки:

| Seafarers preset | Ports на sea-only ребре | Ports без land на обеих конечных вершинах |
| --- | --- | --- |
| simple_1 | 5/9 | 4/9 |
| simple_2 | 8/9 | 7/9 |
| gold_haven | 4/9 | 2/9 |
| pirate_lanes | 4/9 | 3/9 |

Последняя колонка означала недоступные порты. S2A исправила placement новых maps; historical saved ports не переставляются и не проходят новую build validation при recovery. Board3D теперь направляет круглый badge по local land→edge normal; dock/endpoints остаются по исходным IDs. SVG и art не менялись.

### Shape

Всегда берётся список q/r из JSON. Общий builder способен материализовать больший остров, раздельные острова или архипелаг из custom JSON, но не выбирает такую форму автоматически и не проверяет её пригодность для полноценного сценария.

Historical S2A shape change for the original 12 presets: до S2A все имели 19 одинаковых координат и одну land component. Gold Haven получил острова 8+7, Pirate Lanes — 7+6; море связно, даже общей land vertex между островами нет. Sea Ring остаётся одним островом и расширен до 19 land: старый девяти-land layout дал four/30 randomized six-player setup deadlocks после 10–11 settlements. У этих custom presets нет ограничения стартовых островов: setup разрешён на любой engine-legal land вершине, затем anchored road либо sea/coast ship. Room поддерживает 2–6; S3A official варианты отдельно требуют exact 3/4 и main-island setup. Официальные 5–6-player extension mechanics не добавлены.

### Seed

build_game создаёт `random.Random(seed)` и передаёт один поток в materialization/ports, затем перемешивает development deck. При одинаковых данных, порядке tiles, size, seed и версии алгоритма карта повторяется. Один seed без map definition/версии не является полным идентификатором карты.

Seed задаёт terrain shuffle, number shuffle и порядок типов auto ports. Не задаёт shape, положения auto ports или фиксированные terrain/number/explicit ports. Изменение предыдущего RNG-потребления меняет последующие shuffle.

В multiplayer _start_match создаёт seed через secrets.randbits(64), но затем отдельно перемешивает dev_deck через SystemRandom. Dice тоже серверные и независимые от map seed. Клиент seed не получает. Поэтому reproducible map не равна reproducible multiplayer game.

validate_map_data теперь проверяет unique integer q/r (bool запрещён), допустимые terrain/deck values, достаточность terrain deck, number domain без 7 и явные номера sea/desert. **Historical validation bugs — исправлены S2A:** terrain_deck=["lava"], number_deck=[7] и duplicate q/r теперь отклоняются с MapValidationError, без изменения input. Импорт принятого JSON всё ещё не доказывает игровую пригодность. Fog, exploration, island rewards, специальные цели и токены не возникают от arbitrary JSON fields; они planned.

**Historical gameplay finding — superseded by S1:** на checkpoint 3cd8812 `can_place_settlement(require_road=True)` учитывал только свою дорогу; mixed routes/ship movement были частичными. Сейчас Seafarers допускает связь поселения через свой корабль с сохранением land/distance/cost/supply checks. S1 реализует mixed Longest Trade Route, переход road↔ship только через свою постройку, maritime closure и ship-turn lifecycle. S2A добавляет production archipelagos/coasts; scenario start regions/bonuses/fog остаются planned S2B/S2C. Board3D использует серверные цели и не подменяет правила.

## Web rendering: порядок исполнения

1. **LobbyPage:** выбор пресета → WSClient.setMap(mapId); файл → FileReader.onload → JSON.parse → WSClient.setMap(undefined, data).
2. **WSClient.setMap:** отправляет `{type:"set_map", map_id?... , map_data?...}`.
3. **websocket_endpoint → _dispatch/_dispatch_impl:** после protocol/session checks берёт `room.lock`, проверяет ownership/host/lobby, вызывает `_set_map` на `clone_room(room)`. `_commit` сохраняет candidate и только затем публикует новую map revision; Room хранит selected_map_id/selected_map_data и metadata.
4. **start_match → _dispatch_impl → _start_match(candidate, rebind=False):** под тем же lock создаёт seed/игру с подтверждённой картой и current ruleset marker; durable COMMIT предшествует promotion/socket binding и публикации. `_start_and_notify` — отдельный helper, не основной WS dispatch путь.
5. **rules.build_game:** map_data → map_path → preset по приоритету; maps.build_board_from_map → _materialize_tiles → board_geom.build_graph_from_tiles → ports → BoardState; parse_rules_config → GameState.
6. **_send_match_state → _snapshot_state:** serialize.to_player_dict делает персональный view; `_legal_moves(g, pid)` вызывает board_legal_moves. F2 restricted match вместо этого публикует только безопасный room_state, без legal/match_state.
7. **net_protocol.match_state_message → _publish_match_state:** JSON с room_code, match_id, tick, state отправляется только актуальному controlling socket с действительным владением (F1), после durable COMMIT.
8. **WSClient.handleMessage / match_state:** проверяет room/match/tick, сохраняет MatchState, обновляет youPid и вызывает onMatchState.
9. **App.onMatchState → setMatch:** новый React state; App передаёт match в GamePage.
10. **GamePage:** useBoardInteraction хранит локальный selection, createBoardInteraction создаёт callbacks; BoardRenderer получает `{state, interaction}`. Default 3D, SVG 2D доступен через selector.
11. **BoardView / Board3D:** tiles/vertices/edges/occupied_*/ports → SVG либо Three scene; bounds из фактических координат, прежние IDs сохранены. Renderer вызывает `interaction.onVertexClick/onEdgeClick/onTileClick`, не вычисляет gameplay.
12. **Клик:** controller формирует прежние place_settlement/upgrade_city/place_road/build_ship/move_ship/move_robber/move_pirate payloads. WSClient.sendCmd → validated dispatch → room lock → candidate `_apply_cmd`/rules.apply_cmd → COMMIT → promotion → шаг 6. Полный маршрут — [[Сценарий сетевой партии]].

TypeScript: RoomState описывает map catalog/выбор; MatchState содержит персональный state. BoardView.types.Tile уже объявляет optional q/r/center, GameState — geometry/pieces/pending и персональный LegalMoves. `vertex_adj_hexes` остаётся в wire и не нужен текущему renderer/controller; не следует путать его отсутствие в этом UI interface с отсутствием в серверном snapshot.

Renderer строит поле из данных и не обязан знать preset. SVG portRatioLabel показывает ratio; 3D PortReadout3D дополнительно отображает специализацию ресурса. Оба используют существующие port edge/vertex IDs. S2A исправляет новые auto ports в loader, а не скрывает ошибки исторического snapshot визуализацией.

## Готовность к Board3D

**Геометрии snapshot достаточно для 3D-представления существующих открытых карт.** Сохраняется путь GameState → player-specific snapshot → React → renderer. Не требуется менять правила, JSON-пресеты или общий Python engine ради объёмных tiles/figures.

coordinates.ts может преобразовывать уже готовые (x,y) в (x/scale, elevation, y/scale), брать midpoint/направление edge и позицию vertex. Hover/click несёт исходные tile index, vid или [a,b]. Визуальная высота не меняет topology.

Правила остаются на сервере/в движке. Board3D отображает state/готовые targets и вызывает callbacks существующих команд. Это уже реализованная граница: useBoardInteraction выше renderer владеет action/ship source/victim/waiting; SVG и Three используют один controller.

## Будущий Random Map Generator — предложение, не реализация

Три режима следует различать:

- **Preset:** финальная фиксированная карта, без неожиданного auto shuffle.
- **Shuffle:** фиксированные coordinates и land/sea mask; явно выбранные terrain/numbers/port types перемешиваются с сохранением конфигурации и ограничений.
- **Generated:** seed сначала создаёт координаты/острова, затем содержание; готовый результат передаётся существующему map loader.

Нынешние presets фактически смешивают первые два режима. Их поведение нельзя автоматически менять под новые названия.

```text
seed + generator_version + scenario/profile + constraints
  → topology
  → terrain distribution
  → number placement
  → placement/balance validation
  → ports
  → scenario validation
  → final MapDefinition (schema v1, насколько её хватает)
  → существующий build_board_from_map / build_game
```

Предлагаемое место — отдельный модуль рядом с engine/maps.py. Generator возвращает полностью материализованные значения; loader остаётся потребителем, а React только отображает итог. Для multiplayer генерация/валидация принадлежит серверу.

| Этап | Ответственность / ограничения |
| --- | --- |
| Topology | Unique q/r; заданные размеры, land/sea mask, число островов, расстояния и связность; пригодные стартовые land-вершины |
| Terrain | Точные квоты ресурсов, desert/gold/sea и закреплённые клетки; правила профиля для пустынь/золота, а не универсальная произвольная норма |
| Numbers | Номер только на производящей клетке; заданный number multiset; политика 6/8 adjacency по профилю |
| Balance | Вес номера = 6-abs(7-number) исходов из 36; сумма/разброс по ресурсам, островам и стартовым вершинам; допустимые диапазоны, не обещание идеального равенства |
| Ports | Уже есть настоящая land/sea coast validation в S2A; будущий generator должен дополнить её constraints профиля для spacing/count/types |
| Scenario | Разрешённые start islands/zones, pirate sea position, gold quotas, цель/правила выбранного сценария; непредставимые/неподдержанные механики отклоняются явно |
| Finalization | Зафиксировать порядок tiles/IDs; построить graph до explicit edge ports; повторно validate; сохранить seed/version/config и итоговый JSON |

Детерминированность требует версионированного алгоритма и стабильных независимых RNG-потоков для topology/terrain/numbers/ports; иначе добавление shuffle меняет остальные результаты. Нужны ограниченный бюджет попыток/поиска и понятный отказ при несовместимых constraints, вместо бесконечного retry.

Базовый Shuffle ближе к готовности: есть materialization и graph. Generated требует topology builder, scenario profiles и содержательной валидации; это отдельная задача. Arbitrary multi-island геометрия и S1 routes уже работают, но custom balance, scenario bonuses/fog/start regions и полнота natural playtests не выводятся из этого автоматически.
