# Стили и визуальные границы

[[React интерфейс]] · [[Web клиент]] · [[Design System]]

Эта заметка описывает существующие границы оформления. Она не предлагает переписывание компонентов.

## Источники оформления

| Источник | Что задаёт |
| --- | --- |
| [styles.css](../../web/src/styles.css) | Прежние global/lobby styles; старые game-grid/res-chip правила больше не задают match composition |
| [game.css](../../web/src/game/game.css) | Match-only fullscreen grid, HUD/dock/hand/drawers/focus и desktop breakpoints; локальные CSS variables в .app.app--match |
| [GameIcon.tsx](../../web/src/game/GameIcon.tsx) | Небольшие собственные SVG glyphs ресурсов/controls, без font/icon package |
| [BoardView.constants.ts](../../web/src/components/BoardView.constants.ts) | UI_STYLES, TERRAIN_COLORS, PLAYER_COLORS, тени, толщины и размеры |
| [BoardView.tsx](../../web/src/components/BoardView.tsx) | SVG-фигуры, часть цветов, координатных смещений и inline-стилей |
| [board3d.css](../../web/src/board3d/board3d.css) | Базовые renderer/container/fallback styles; game.css scoped overrides растягивают Canvas и делают controls компактными |
| [materials.ts](../../web/src/board3d/materials.ts), [TerrainHints.tsx](../../web/src/board3d/TerrainHints.tsx) | Палитра/силуэты 3D terrain; player colors берутся из общего board/constants.ts |

`:root` и .lobby-grid сохраняют оформление lobby. Match использует .app.app--match с dark variables и нулевым padding, .game-shell с minmax(0,1fr) column и fixed HUD rows / flexible scene. Старые .game-grid/.res-chip/.log-box остаются legacy CSS и не используются новым GamePage. Изменения не перекрашивают LobbyPage.

BoardView сохраняет SVG width=100%/height=520 в исходнике; scoped CSS match задаёт фактическую высоту 100% сцены и прозрачный фон. Canvas также 100% доступной области. BoardControls теперь в dock; .game-button имеет общий compact style/hover/focus/disabled treatment. Hand uses resource-specific color + glyph/name/count, player ownership — отдельный PLAYER_COLORS.

Историческая Phase 2 verification 2026-10-05: BoardRenderer сохранял default SVG и lazy 3D Experimental, Canvas ограничен доступной шириной и height=clamp(360px,58vh,620px). Phase 2 подключает оба renderer к общим server targets/callbacks, добавляет небольшие vertex rings, edge prisms и tile outlines. Hover усиливает подсветку, ship source/victim tile выделяются янтарным. Terrain, camera, styles.css и board3d.css не менялись; desktop 1440×1000, 1280×720, 1024×768 проверены без horizontal overflow. Это interaction foundation clean tabletop, не HUD redesign или окончательные visual tokens. Подробности — [[Design System]] и [[plans/board3d]].

## Актуальная match composition — 2026-10-05

Game UX 2.1: fullwidth navy stage без dashboard. Высоты top/bottom HUD 76/116px, при ≤1500px — 72/112px, ≤1300px — 68/108px. Canvas занимает весь оставшийся stage; prompt/view/reset компактно расположены поверх его верхней свободной области, дополнительной пустой строки нет. Grid minmax и truncation player names сохранены. Закрытые overlays не занимают места; log/info fixed к viewport, чтобы вложенный victim drawer не зависел от позиционирования action dock.

Three markers визуально меньше/прозрачнее, hover сильнее, selected amber; прежние hit surfaces и callbacks сохранены. Ports — небольшой тёмный token с цветным resource rim и двумя branches к точным endpoints supplied edge. portLabelPosition/portConnectors/cameraFootprint содержат только visual geometry. Game UX 2.1 добавляет статическую плотность terrain и небольшие детали pieces при исходных IDs, ownership, координатах и TILE_TOP. Default 3D, selector/reset компактны; tile-index footer удалён.

Direct dock uses ActionButton/cost preview on hover/focus, включая disabled wrapper keyboard focus. ResourceCard задаёт одинаковый визуальный язык hand/tray/offers; quantities сохраняются из snapshot/local draft. Nonmodal Trade Tray находится над рукой, без +/- таблицы. DiceHUD — две pip faces; Three animation только для подтверждённого pair, 950ms, без permanent loop; CSS поддерживает reduced motion. Game log содержит collapsible public Bank availability. 108 web/203 pytest, TS/build/Docker и 17 Chrome cases проверены на 1920×1080, 1440×900, 1280×720. Эти проверки не повторяли six-player/mobile/low-end certification; подробности — [[Design System#Game UX 2.1 — implemented direct tabletop UX]] и [[plans/game-ui-redesign#Game UX 2.1 — Direct Actions / Trade Hand / Dice / Board Readability]].

Историческая UI Phase 1 verification: 73 web tests, TypeScript, production/Docker build и Chrome screenshots прошли. Base/Gold проверены 1920×1080/1440×900/1280×720 без page scroll, hand/dock overlap и clipped buttons. Modal discard/gold сохраняют значения/commands и keyboard focus trap; victim nonmodal сохраняет view switching. На этом этапе terrain raycast occlusion не исправлялась. Scope/evidence — [[plans/game-ui-redesign]] и [[Design System]].

**Polish 1.1, verified 2026-10-05:** дополнительный шестисегментный RingGeometry над tile удалён: его контур был повёрнут на 30° относительно настоящего hex. Hover/legal/selected используют небольшие emissive варианты самого top material; shared neutral material не мутируется. Vertex/edge hit surfaces полностью прозрачны, а декоративный terrain не raycast-ится. Компактные портовые placards ориентированы по существующим edges, соединены небольшим dock; server placement не меняется. Terrain details немного варьируются по исходному tileIndex, bevel/depth увеличены при прежнем TILE_TOP. Полный azimuth разрешён при прежних polar/zoom limits. CSS/HUD/controller не менялись. 76 tests, TS/build/Docker/Chrome прошли; evidence — [[Design System#Polish 1.1 visual evidence]].

## Связь с поведением

| Часть | Что можно менять в оформлении | Какие связи сохранять |
| --- | --- | --- |
| Заголовок, фон, карточки | Цвет, шрифт, отступы, границы | Отображение вложенного содержимого |
| Ресурсы | Вид карточки, подпись, расположение | Ключ ресурса k и количество res[k] |
| Список игроков | Вид строки, маркеры, расположение | pid, name, vp/connected/host |
| Статус и журнал | Типографика, контейнер, раскладка | Исходные значения, тексты ошибок |
| Формы | Внешний вид контролов | value, onChange, min/max и обработчик отправки |
| Кнопки | Цвет, размер, подпись | onClick и disabled |
| Поле | Изображение фигур и клеток | Геометрия, ID, hit areas, порядок SVG-слоёв, клики и legal |

GamePage и LobbyPage сохраняют связи с командами/сетевыми действиями. BoardView и Board3D после Phase 2 используют renderer-neutral interaction props: визуальную часть можно менять, сохраняя оригинальные IDs, target membership и callbacks. Shared controller не рассчитывает gameplay rules. Простые текстовые панели и карточки ресурсов имеют меньше поведенческих связей.

В constants лежат также ActionType, CommandType, GamePhase и SETUP_TYPES. Эти значения участвуют в поведении; они не являются визуальными токенами. `edgeKey` связывает данные дороги с ключом occupied_e; `hexCorners` и `calculateBounds` связывают рисунок с геометрией.

Props поля описаны в [BoardView.types.ts](../../web/src/components/BoardView.types.ts). Типы — описание контракта, а не runtime-валидация. Известные несоответствия контракта отмечены в [[Результаты аудита]].

2026-10-02: несоответствия Port и состояния исправлены при согласовании приватного network view, TypeScript проходит. CSS/SVG и визуальная композиция React не менялись. Runtime validation сетевого JSON остаётся отдельным ограничением клиента.
