# Стили и визуальные границы

## Audio presentation boundary — 2026-10-08

Product / UX / Visual Polish Phase 4 adds [audio.css](../../web/src/audio/audio.css) only for the header speaker entry and a compact 300px GameOverlay popover. Scoped `.game-shell .audio-settings-popover .game-drawer` wins over legacy drawer dimensions; sidebar/footer variables keep it inside the board area with bounded height and internal scroll. Existing navy/sand/seafoam tokens, inputs/focus/close conventions remain. Permanent Chat, Game Log, Test Mode, hand/dock, 2D/3D controls and all board art remain unchanged. Temporary settings cover part of the board, never add a permanent sidebar; mandatory choices/result dialogs keep priority.

Audio is optional presentation downstream of personalized committed snapshots, never a controller/rules dependency. Shared original recipes create finite native nodes, not downloaded assets or per-frame React state. Dice sounds follow existing visual timing; grouped resources and generic theft avoid spam/private identities. Music is explicitly opted in, defaults to 12%, pauses hidden and stops on leaving the match. There is no hover sound, continuous ocean/ship audio or surprise music at load. Browser-local volumes/mute do not change account/database preferences.

Verified: 231 web tests, TS/build, native Chrome 154 Base/Gold acceptance and 1920×1080/1440×900/1280×720 popover/focus layouts without horizontal or Chat/sidebar overflow. No observable audio-related 3D render cost in the same-board off/on/off samples; Base's existing capped ambient boats still render and Gold idle remains zero. Screenshots/provenance — [[Design System#Product / UX / Visual Polish — Phase 4: Audio]], implementation/measurement limits — [[plans/game-ui-redesign#Product / UX / Visual Polish — Phase 4: Audio]]. Older no-audio statements below describe their dated checkpoints.

## Building asset / preview boundary — 2026-10-08

Product / UX / Visual Polish Phase 3B integrates immutable `web/public/models/pieces/{settlement,city,road}.glb` through [pieceAssets.ts](../../web/src/board3d/pieceAssets.ts), [PieceVisual.tsx](../../web/src/board3d/PieceVisual.tsx) and the existing Pieces3D. PlayerColor clones follow existing ownership colors; neutral materials retain source colors. Ghost opacity is isolated from confirmed/other-player materials, and all piece visuals ignore raycasting. No CSS redesign, new art, Blender edit, dependency or HUD/layout rewrite.

The presentation floor is the common terrain rim Y=.218333. Local visual offsets retain the original .26/.32 building/road anchors and all XZ/IDs. Procedural terrain loading/error fallback is lowered to the same visible top; the old coastline strip cap is aligned to it so neither buries GLB foundations. These are shared visible-surface corrections, not changes to game geometry, terrain assets, hit targets, map topology or rules.

Legal City hover hides the owned settlement while keeping it mounted; it is restored on pointer exit/Cancel/Escape. Build prompts/cost/unavailability messages read existing state and controller targets. Setup remains mandatory; dialogs and Chat input retain Escape. Confirmed occupancy alone triggers finite 260ms ref-based scale feedback; reduced motion/restored snapshots do not animate history. No sound, particles, continuous loop or camera change.

Verified 2026-10-08: 204 web tests, TS/build and 10 actual Chrome groups/all 20 acceptance cases. Base/Gold desktop 1920×1080, 1440×900, 1280×720, plus missing-terrain fallback framing, preserve board/HUD/input areas and no horizontal overflow. Asset hashes and all 11 production copies match. Approximate GPU cost is unchanged at the measured scale; mobile/low-end/50-hex remains unverified. Evidence and exact timing limits — [[Design System#Product / UX / Visual Polish — Phase 3B]] and [[plans/board3d#Product / UX / Visual Polish — Phase 3B]]. Earlier sections describe their checkpoints.

## Active match visual boundary — 2026-10-08

Product / UX / Visual Polish Phase 2 reuses [shell.css](../../web/src/shell/shell.css) tokens in `.game-shell` as well as `.app-shell`/`.auth-backdrop`. GamePage does not receive the 1184px PageShell wrapper. [playtest.css](../../web/src/game/playtest.css) maps match surface/text/border variables to the shared palette and owns compact header/sidebar/Chat/Log/overlay layout. Global body, gameplay/controller, ownership/resource palette, original SVG and terrain GLB materials remain separate.

Header is 52px. `--match-sidebar-width` is 286px, 254px at ≤1500px, 240px at ≤1100px; `--match-footer-height` is 138px, 125px, 184px respectively. Narrow footer explicitly uses one column/two rows with the action dock on the right. Board fills the remaining minmax area; camera fit, orbit limits, zoom/reset/selector and number/target geometry are unchanged. Names truncate with full title; at narrow widths the duplicate turn pill is hidden while current-player border/aria-current/prompt and timer remain.

`.game-shell .game-sidebar` deliberately has enough specificity to preserve its flex layout against later-loaded legacy styles.css. Bank is first and compact; Players may shrink/scroll, Chat flexes with always-accessible input, separate Game Log stays closed by default with a bounded `min(14vh,160px)` scroll region. Info/dev/incoming-trade drawers use sidebar/footer variables to stay over the board and clear of Chat/dock. Existing mandatory/test modals retain priority.

Scene decoration belongs to [DecorativeOcean.tsx](../../web/src/board3d/DecorativeOcean.tsx), [AmbientShips.tsx](../../web/src/board3d/AmbientShips.tsx) and [environment.ts](../../web/src/board3d/environment.ts). Static basic-material ocean/texture and neutral procedural Base boats cannot become game hit targets. Boats use capped 10Hz transforms with hidden/reduced pause; Seafarers keeps zero ambient animation. Ports keep original connection paths, replacing only readouts with [PortReadout3D.tsx](../../web/src/board3d/PortReadout3D.tsx) and exact shared GameIcon resource paths. No Blender/GLB/terrain/piece-model change, reflection/refraction shader or extra light.

Verified 187 web tests/TS/build and real Chrome Base/Gold on 2026-10-08. Base 1920×1080/1440×900/1280×720/1024×768/900×800, Gold through 1024×768; Log closed/open and 3-player layouts retain visible Chat/input without horizontal/sidebar overflow or hand/dock overlap. Seven inspected images — [[Design System#Product / UX / Visual Polish — Phase 2]]. Capped Base idle frames supersede historical zero-idle claims for earlier checkpoints; low-end/mobile/50-hex performance is not certified. Older descriptions below are dated history.

Это interaction foundation clean tabletop, не HUD redesign или окончательные visual tokens. Подробности — [[Design System]] и [[plans/board3d]].

## Связь с поведением

| Часть | Что можно менять в оформлении | Какие связи сохранять |
| --- | --- | --- |
| Заголовок, фон, карточки | Цвет, шрифт, отступы, границы | Отображение вложенного содержимого |
| Ресурсы | Вид карточки, подпись, расположение | Ключ ресурса k и количество res[k] |
| Список игроков | Вид строки, маркеры, расположение | pid, name, vp/connected/host |
| Статус и журнал | Типографика, контейнер, раскладка | Исходные значения, тексты ошибок |
| Формы | Внешний вид контролов | value, onChange, min/max и обработчик отправки |
| Кнопки | Цвет, размер, подпись | onClick и disabled |
| Поле | Изображение фигур и клеток | Геометрия, ID, hit areas, порядок SVG-слоёв, клики и legal |

GamePage и LobbyPage сохраняют связи с командами/сетевыми действиями. BoardView и Board3D после Phase 2 используют renderer-neutral interaction props: визуальную часть можно менять, сохраняя оригинальные IDs, target membership и callbacks. Shared controller не рассчитывает gameplay rules. Простые текстовые панели и карточки ресурсов имеют меньше поведенческих связей.

В constants лежат также ActionType, CommandType, GamePhase и SETUP_TYPES. Эти значения участвуют в поведении; они не являются визуальными токенами. `edgeKey` связывает данные дороги с ключом occupied_e; `hexCorners` и `calculateBounds` связывают рисунок с геометрией.

Props поля описаны в [BoardView.types.ts](../../web/src/components/BoardView.types.ts). Типы — описание контракта, а не runtime-валидация. Известные несоответствия контракта отмечены в [[Результаты аудита]].

2026-10-02: несоответствия Port и состояния исправлены при согласовании приватного network view, TypeScript проходит. CSS/SVG и визуальная композиция React не менялись. Runtime validation сетевого JSON остаётся отдельным ограничением клиента.
