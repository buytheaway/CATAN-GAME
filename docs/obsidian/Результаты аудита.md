## Подтверждённые расхождения

- Публичная grant_resources доступна через серверный обработчик.
- Клиентский roll принимается при отключённом debug.
- join_room с чужим именем повторно связывает существующий слот.
- Приняты несуществующая вершина и индекс разбойника; несуществующее ребро признано допустимым проверкой дороги.
- Year of Plenty позволил выдать 20 ore при запасе 19, банк стал −1.
- Ошибочная Monopoly расходует карту до ошибки.
- Сохранение JSON меняет ключи dev_played_turn/free_roads на строки; загрузка не нормализует их.
- Комната на четыре места может стартовать с двумя участниками и четырьмя игроками в game.

## Связь с визуальной подготовкой

Trade и карты развития не имеют web-форм. Главное меню и отдельный победный экран отсутствуют. Стили смешаны между CSS, constants и SVG. BoardView связан с обработкой команд, GamePage — с доступностью действий, LobbyPage — с сетевыми операциями. Полная карта: [[Стили и визуальные границы]].

Заметка фиксирует состояние и ограничения; она не вносит изменения и не объявляет спецификацию выполненной.

Для pirate индекс/sea были уже проверены; недостаток общего coordinate path подтвердился у settlement/road/robber. Sequence advance на отказе подтверждён, но признан допустимым consumed-sequence контрактом, а не сам по себе игровым багом.

## Pirate repeated theft P0 — fixed 2026-10-02

До изменений воспроизведена партия seafarers_pirate_lanes с законной setup-расстановкой и двумя build_ship после roll. При main/turn=0/rolled=false/pending=None три последовательных move_pirate между sea tiles 6 → 11 → 6 приняты: украдены wood, wood, sheep. Причина: pirate branch проверяла сценарий, фазу/ход, sea tile и victim, но требовала отсутствия pending вместо наличия разрешённого события. Во время robber_move pending gate разрешал только robber.

Исправление сохраняет pending имя и network shape: 7 после discard либо Knight → robber_move с pending_pid → выбор robber или pirate при enable_pirate → полная валидация клетки/жертвы → движение и максимум одна кража → очистка pending. Следующая pirate команда требует нового события. Жертвы pirate определяются соседними кораблями, robber — постройками; отдельной команды pirate theft нет. React/PySide map clicks согласованы с выбором фигуры, без redesign.

## Phase 1 final verification — 2026-10-03

**Completed. READY FOR CHECKPOINT** в утверждённом scope. Новый общий аудит не проводился; проверены два продуктовых решения и повторён полный доступный набор регрессий.

VP policy уже соответствовала runtime: active total=7 с двумя hidden VP cards отображался сопернику как 5, после game_over — как 7; сама рука оставалась закрытой. Новый реальный WS regression создаёт legal VP purchases для обоих игроков, проверяет собственный total/чужой public VP и завершает матч production buy_dev-командой. После завершения оба клиента получают итоговые VP всех игроков, включая проигравшего; чужая res/dev_cards, bank и deck по-прежнему скрыты. serialize.py в финальной задаче не изменялся.

Rematch раньше отвергал старт при отсутствии любого прежнего участника. Удалён этот barrier, использована существующая фильтрация connected participants и compact pid mapping. Подключённый host сохраняет право старта; при его отключении первый connected участник может запустить rematch и становится host после успеха. Проверены минимум два игрока, сохранение старой identity при отказе, восстановление отключённого игрока до rematch, исключение его token после старта, отсутствие пустых PlayerState, retained token с новым pid, новый match_id/seq/cmd_id history и отзыв старого WebSocket. Runtime финального шага изменён только в server_mp.py.

## Аудит постоянной памяти

Проверено 2026-10-01. Исходные 18 заметок покрывают пути desktop/web/server/engine, состояние, карты и пользовательские правила. Их роли перечислены в [[00 Главная]].

Обнаруженное повторение имеет разные цели: Точки входа кратко пересказывает запуск из заметок клиентов; Сценарий сетевой партии связывает их в последовательность; React интерфейс описывает блоки, Web клиент — транспорт; краткие правила пересказывают полный первичный текст. Сохранять ссылки и эти границы, не создавать вторую Architecture или ещё один UI-справочник.

Результаты аудита — исторические проверки, а не актуальный статус. Отдельной сводки состояния, ADR, политики документации, design register и структуры планов раньше не было; теперь эти роли выполняют [[Project State]], [[Architecture Decisions]], [[Documentation Policy]], [[Design System]] и [[plans/README]].

Статическая сверка актуального кода подтверждает существование путей grant_resources/roll, входа по имени, удаления карты до валидации, строковых ключей загрузки и несброшенной browser seq. Сохранены расхождения со спецификацией; утверждение «сервер авторитетен» трактуется как требование, не доказанная гарантия. Детальное поведение клиентских подсказок, первый desktop snapshot и остальные тестовые результаты не перепроверялись исполнением в задаче памяти.

Потенциально устаревающие сведения: числа тестов, версии/состояние установленных зависимостей, строки исходников и статус багов. Проверять заново перед изменением соответствующего поведения; не выдавать прошлый зелёный build за текущую проверку. Новые ADR отражают утверждённое направление, а не автоматически изменённую архитектуру. Невидимые макеты не использованы для описания стиля.
