# Состояние игры

## Trusted fog persistence — S2B-2B.1

Implemented **2026-10-09**, public availability **DISABLED**. GameState still has 43 fields; the existing `scenario` now contains:

| Trusted record | Stored values |
| --- | --- |
| `ScenarioRules.fog: FogRules or None` | `profile="shared-preassigned-v1"`, ordered unique tuple `initially_hidden` of original tile indices |
| `ScenarioState.fog: FogState or None` | `assignment_digest`, shared `revealed` frozenset, ordered `discoveries` tuple, optional `continuation` |
| `FogDiscovery` | `tile_index`, discoverer `pid`, `reward_status` none/pending/awarded/unavailable, optional ordinary `resource` |
| `FogContinuation` | original `command` place_road/build_ship/move_ship, `pid`, original `edge` pair, `setup` boolean |
| Existing `BoardState.tiles` | Actual preassigned terrain/number values, never a second hidden board |

The digest covers tile order/q/r/terrain/number. Codec validation rejects changed assignments, invalid masks, duplicate/missing reward entries and inconsistent pending Gold/continuation state. Same-match commit validation additionally forbids rehashing changed assignments, hiding a discovery, removing/reordering or rewriting completed rewards and changing geometry/ports. These are foundation fences, not an exploration/reward executor; tests with recorded discoveries are explicitly synthetic trusted histories.

Current trusted writer [snapshots.py](../../app/persistence/snapshots.py) is **v4 / engine_compatibility=3**. Exact **v1/1, v2/1, v3/2** decode via released schemas; v3's ScenarioRules/ScenarioState fields are frozen separately from v4. Old states get `fog=None`, retaining old scenario/ship-history semantics and recorded VP/achievements. Restore does not rebuild/shuffle/reveal/award or run gameplay. Room checkpoint stays v1; no SQL migration or old snapshot rewrite.

New match marker is `catan-seafarers-s2b-2`, independent of codec. Existing verified S2B-1/eligible S1 non-fog markers remain immutable/compatible; unknown markers remain restricted. A stored fog fixture is readable but **restricted regardless of marker**, including finished state. Account/guest Continue and takeover may update ownership metadata only, without timer resume or private match_state/head/result change. Public/offline serialization and Qt conversion reject fog; they must not fall through to the public ordinary map projection. Details — [[Architecture Decisions#ADR-018 — Trusted fog foundation with public feature disabled]], [[plans/seafarers-fog]].

Rollback: a pre-v4 binary cannot read a v4 head; retaining an S1/S2B-1 marker does not make the format backward writable. There is no automatic conversion or fallback to a predecessor.

## Snapshot format versus match ruleset — F2

Historical F2 checkpoint below. Current writer is v4/3 and new match marker is S2B-2; the immutable provenance/unknown restriction policy remains in effect.

Verified **2026-10-08**. The trusted engine codec still reads v1/v2, writes v2, engine_compatibility=1; the private Room wrapper remains room_snapshot_version=1. These versions describe structural decoding only. **Gameplay provenance is a separate nullable `matches.ruleset_id`**, copied into Room on recovery and explicitly assigned only by new `_start_match`. It is not inferred from GameState.state_version, dates, codec or scores and is not attached by rewriting existing snapshots.

Additive migration [f2a001_match_ruleset.py](../../migrations/versions/f2a001_match_ruleset.py) adds one nullable text column with no default/backfill. New matches use `catan-seafarers-s1`; NULL or unrecognized identifiers retain readable state but cannot execute current rules. Recovery does not recompute route ownership/length, achievements, VP or winner. Finished results retain original metadata/participants/head. Valid unknown rules are a compatibility restriction, not invalid snapshot data; genuinely malformed heads still follow strict corruption handling.

Metadata-only Continue/claim/leave/chat may update room/member/token rows, but skip old match/participant/result upserts and never write/prune an old head. Recovered timers remain inert; no resume checkpoint is written. Commit transition checks compare the restricted GameState/epoch/tick/timer, reject snapshot/receipt writes and marker changes; PostgreSQL also validates the stored marker under row lock. Normal current creation/command commits include the marker atomically; ambiguous commit resolution checks it. No ruleset lives solely in RAM in durable mode.

Known-current matches may use a readable v1 format with ADR-014's conservative ship-history lock; **unknown v1 and unknown v2 are both blocked**. Dropping/recreating the column loses provenance, so re-upgrade safely restricts affected records; rollback to a binary ignoring the gate is unsafe. Strategy D conversion is **not implemented**; any future explicit reconciliation needs a separate approved maintenance design. Policy — [[Architecture Decisions#ADR-015 — Match ruleset provenance and safe legacy restriction]], verification — [[Project State#Match ruleset compatibility — F2]].

В GameState есть свойства `tiles`, `vertices`, `occupied_v` и другие, которые обращаются к вложенному board. Поэтому правила часто пишут g.tiles, хотя данные находятся в g.board.tiles.

## Словарь полей

- `pid` — индекс игрока, начиная с 0; UI пишет P1 для pid=0.
- `vid` — ID вершины; это не координата x.
- `eid` — пара ID вершин ребра.
- `tile` — индекс клетки в tiles.
- `occupied_v[vid] = (pid, level)`, где level=1 — поселение, 2 — город.
- `occupied_e[(a,b)] = pid` — владелец дороги.
- `legal` — персональные серверные списки доступных board targets; legal.pid — получатель. Affordability/pieces/roll/pending/free-build и victims проверяет engine, чужой игрок не получает эти hints.

JSON превращает ключи словарей в строки. Рёбра сериализуются как ключи вида `"12,19"`. При чтении Python и TypeScript важно учитывать этот формат.

## Три разных состояния

1. GameState — изменяемая модель движка на сервере.
2. Снимок JSON — представление для клиента.
3. Локальное состояние UI — GamePage.useBoardInteraction selection (action, shipSource, victim, waiting), discard, goldRes/goldQty, tradeDraft (Give/Want) и конечные dice/robber/card animations. Selection общий для SVG/Three и не является GameState; draft не списывает hand, Three не генерирует бросок.

TypeScript-интерфейс GameState в BoardView.types.ts описывает ожидаемые данные поля и не является Python-классом GameState. Он не создаёт объект и не проверяет JSON во время исполнения.

В desktop также есть отдельный `ui_v6.Game` с Qt-координатами. `Room.tick` и `GameState.tick` — разные поля; текущий сервер увеличивает первый.

Network envelope не содержит seed. Геометрия приходит полностью; восстанавливать карту/колоду по seed клиенту не нужно. Подробнее: [[Сервер и протокол]] и [[Architecture Decisions]].
