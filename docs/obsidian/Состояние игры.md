# Состояние игры

## Durable Room checkpoint — Persistence 1B

Verified **2026-10-06**: PostgreSQL хранит private engine envelope codec v1 внутри отдельного Room checkpoint v1. [recovery.py](../../app/persistence/recovery.py) содержит `room_config`, `match_checkpoint`, `restore_room` и `resume_timer`; [repositories.py](../../app/persistence/repositories.py) сохраняет aggregate в одной transaction. Engine codec и network serializer не изменены.

| Durable surface | Содержимое |
| --- | --- |
| rooms / versioned config | UUID/code/status/host/current match/tick/revisions; полный выбранный preset/custom source, meta/effective rules, RoomSettings с nullable target_vp; chat 50, Test flag, UTC activity/close/expiry |
| room_players / seat_tokens | Stable member UUID, current pid/name/color/status; SHA-256 bearer hash, expiry/revocation. Raw token, WS, connected и locks отсутствуют |
| matches / match_players | Match UUID + room-scoped integer epoch; map/settings/status/timestamps; participant UUID/pid, consumed seq, final total VP/winner |
| game_snapshots.payload.engine | Полный immutable codec v1: GameState с готовой board geometry/IDs, private deck/cards/bank/pending/free_roads/achievements/history |
| game_snapshots.payload.runtime | seed consistency, balanced_v1 + exact ordered remaining bag, confirmed dice/count, timer pid/stage/aware UTC deadline, canonical private events 80/serial, test-only forced pair |
| command_receipts / room_operations | Последние 256 command outcomes per MatchPlayer и 256 lifecycle/config request IDs per Room; payload hash, classification/result markers |

Room checkpoint содержит room_snapshot_version=1, durable UUID/epoch/tick, engine envelope и runtime. JSON-normalized checksum проверяется перед restore; integer event audience keys восстанавливаются явно. SQL head — current + два diagnostic predecessors; старый snapshot не используется как automatic fallback. Room.durable_revision учитывает metadata/rejections, которые не увеличивают Room.tick; head revision может быть меньше aggregate revision. Room.tick и GameState.tick не смешиваются.

Recovery не вызывает build_game/map generation/deck or bag shuffle. Все PlayerSlot сначала disconnected, raw token отсутствует до получения verified proof. Monotonic deadline реконструируется из UTC, timed match paused до reconnect; chat rate window runtime-only. Точные held hands/dev/VP/bank/pending остаются только на сервере и идут клиентам через прежние `to_player_dict`/`game_events.project`, не через persistence payload. Free roads восстанавливаются только в текущем lifecycle; прежний End Turn cleanup сохранён.

Qt Game/save формат не переведён на новый codec. Без configured durable mode локальный dev по-прежнему RAM-only. Полная схема/recovery/privacy/ограничения — [[plans/persistence-auth#Persistence Phase 1B — implementation and verification]], [[Сервер и протокол#Durable command and recovery flow — Persistence 1B]].

## Full trusted persistence codec v1

**2026-10-06, Persistence Phase 1A Completed.** [snapshots.py](../../app/persistence/snapshots.py): encode_snapshot/decode_snapshot работают с JSON-compatible dict, dumps_snapshot/loads_snapshot — с UTF-8 JSON text. Envelope `{snapshot_version:1, engine_compatibility:1, state:...}` хранит все 40 GameState fields и вложенные BoardState/PlayerState/Tile/RulesConfig/AchievementState/TradeOffer, включая seed, точную колоду/личные карты/new flags/VP, bank, pending, free_roads, setup, offers и engine tick/state_version. Не использовать этот PRIVATE payload как network snapshot.

Board сохраняется готовым, с прежними tile order/vertex IDs/edge pairs/adjacency/ports/occupancy; restore не вызывает build_game или graph builder. JSON decimal pid/vid keys и `a,b` edge keys восстанавливаются централизованно; coordinates/edges/occupancy/ports снова tuples, edges/discard_submitted — sets. Все изменяемые структуры независимы. Properties GameState — aliases board/achievements; remaining pieces и port ownership вычисляются из сохранённых данных, отдельного поля в Python PlayerState нет.

Строгие версии/обязательные shape/type/reference checks и duplicate JSON-key detection дают SnapshotError subclasses вместо silent defaults/repair. Full nested equivalence/type comparisons и продолжение commands проверены 179 cases; полный pytest 445/445. Player-specific serializer и server projection не изменены: чужие exact hands/dev types/active hidden VP, Hidden bank, seed/deck и codec envelope не раскрываются. Подробности формата/лимитов/замеров — [[plans/persistence-auth#Persistence Phase 1A — completed 2026-10-06]].

**GameState codec ≠ Room checkpoint.** Room identity/ownership/seq/bag/timer/chat/revisions остаются вне GameState; Phase 1B сохраняет их отдельным aggregate выше. Сокеты/connected/monotonic values не сериализуются. На checkpoint 1A backend ещё терял партии; durable mode 1B восстанавливает их. Qt Game и `_offline_hidden` save не переписаны; исправление их string-key bugs/переход на codec — отдельная задача.

## Где лежат данные

| Данные | Сервер / движок | Браузер |
| --- | --- | --- |
| Вся партия | Room.game → GameState | App.match.state и WSClient.matchState.state |
| Игроки партии | GameState.players: PlayerState[] | state.players |
| Места в комнате | Room.players: PlayerSlot[] | App.room.players |
| Ресурсы игрока | PlayerState.res | Своя res; у чужих только resource_count |
| Карты развития | PlayerState.dev_cards, GameState.dev_deck | Свои dev_cards; у чужих dev_count, deck отсутствует |
| Ресурсы банка | GameState.bank | bank_available всегда; bank counts только при Room bank_visibility=visible |
| Карта | GameState.board: BoardState | tiles, vertices, edges, ports в state |
| Постройки | board.occupied_v/e/ships | occupied_v/e/ships |
| Текущий игрок | GameState.turn | state.turn |
| Этап партии | GameState.phase | state.phase |
| Бросок выполнен | GameState.rolled | state.rolled |
| Сумма / история бросков | GameState.last_roll / roll_history | Прежние total значения |
| Реальные грани последнего броска | Room.dice / roll_count — public presentation metadata | state.dice / roll_count → DiceHUD / finite DiceRoll3D |
| Настройки комнаты | Room.settings / config_revision, preset RulesConfig | room.settings + pending intents WSClient; state.room_settings в матче |
| Цвета | PlayerSlot.color независимо от pid | room/state.players[].color → общий colorForPlayer |
| Balanced RNG | Room.dice_bag / dice_algorithm=balanced_v1 | Bag/version internal; видны только confirmed dice |
| Timer | Room.timer: runtime monotonic; persisted UTC/stage/pid и recovery pause | state.turn_timer → current HUD remaining countdown |

| Комнаты | RoomManager.rooms | Только данные присоединённой комнаты |

В GameState есть свойства `tiles`, `vertices`, `occupied_v` и другие, которые обращаются к вложенному board. Поэтому правила часто пишут g.tiles, хотя данные находятся в g.board.tiles.

## Словарь полей

- `pid` — индекс игрока, начиная с 0; UI пишет P1 для pid=0.
- `vid` — ID вершины; это не координата x.
- `eid` — пара ID вершин ребра.
- `tile` — индекс клетки в tiles.
- `occupied_v[vid] = (pid, level)`, где level=1 — поселение, 2 — город.
- `occupied_e[(a,b)] = pid` — владелец дороги.
- `legal` — персональные серверные списки доступных board targets; legal.pid — получатель. Affordability/pieces/roll/pending/free-build и victims проверяет engine, чужой игрок не получает эти hints.

JSON превращает ключи словарей в строки. Рёбра сериализуются как ключи вида `"12,19"`. При чтении Python и TypeScript важно учитывать этот формат.

## Три разных состояния

1. GameState — изменяемая модель движка на сервере.
2. Снимок JSON — представление для клиента.
3. Локальное состояние UI — GamePage.useBoardInteraction selection (action, shipSource, victim, waiting), discard, goldRes/goldQty, tradeDraft (Give/Want) и конечные dice/robber/card animations. Selection общий для SVG/Three и не является GameState; draft не списывает hand, Three не генерирует бросок.

TypeScript-интерфейс GameState в BoardView.types.ts описывает ожидаемые данные поля и не является Python-классом GameState. Он не создаёт объект и не проверяет JSON во время исполнения.

В desktop также есть отдельный `ui_v6.Game` с Qt-координатами. `Room.tick` и `GameState.tick` — разные поля; текущий сервер увеличивает первый.

## Network privacy — verified 2026-10-02

Уточнение **2026-10-06, Game / Room UX 2.2**: to_player_dict сохраняет прежнюю private projection. Server _snapshot_state добавляет только принятые public room_settings/color/timer и копию bank при Visible (новый default); Hidden bank по-прежнему отсутствует. RNG bag, seed, deck/count/order и foreign hands/active hidden VP не добавляются. Visible bank намеренно допускает two-player deduction. Настройки/таймер/chat/bag живут в Room, не создают второй GameState. Reconnect сохраняет их, rematch сохраняет options/colors/history и сбрасывает timer/bag/dice/sequence. Server remaining использует monotonic clock, React elapsed — performance.now. Полная проверка: 234 pytest, 119 web и 19 Chrome cases; [[Сервер и протокол#Room policy — Game / Room UX 2.2]].

Trusted `serialize.to_dict` не используется как multiplayer view. `to_player_dict(g, pid)` удаляет чужую res, скрывает VP-карты в чужом vp до game_over, добавляет собственные dev_cards и public resource_count/dev_count. Собственные pending_gold/discard_required фильтруются по pid. Фаза, очередь ожидающих игроков, фигуры, trade offers и карта публичны; создание view не меняет исходный GameState.

`_snapshot_state` добавляет you_pid/legal и с Game UX 2.1 публичные dice/roll_count. Браузер использует серверный you_pid после уплотнения слотов. Desktop converter хранит чужой resource_count и внутреннюю res с нулями как отсутствие данных, а не реальную пустую руку; hand_size использует count. Bank panel показывает availability. Offline сохраняет полные данные.

Game UX 2.1 verified 2026-10-05: GameState и to_player_dict не изменены. Room хранит только последнюю подтверждённую pair и counter для представления, engine получает прежнюю сумму. End сохраняет pair в Room, новый match сбрасывает null/0; reconnect читает Room, persistence отсутствует. Exact bank/foreign hands/seed по-прежнему скрыты. Формат/atomicity — [[Сервер и протокол#Authoritative dice faces — Game UX 2.1]].

Board3D Phase 2 verified 2026-10-05: legal расширен в engine/legal.py, но to_player_dict и gameplay GameState не изменены. robber/pirate tiles/victims и move_ship.sources/targets используют исходные IDs; server legal projection выполняет команды на копиях и сохраняет полное равенство исходного состояния. Renderer switch меняет только представление; ни state, ни network tick не меняются. Формат/ограничения — [[Сервер и протокол#Personal board legal — Board3D Phase 2]].

Room.max_players — lobby capacity; GameState.max_players — фактические участники. Pid после первого старта последовательны; room/connection/token обновляются вместе. Reconnect_token содержит match_id; seq/pending принадлежат room+match.

Network envelope не содержит seed. Геометрия приходит полностью; восстанавливать карту/колоду по seed клиенту не нужно. Подробнее: [[Сервер и протокол]] и [[Architecture Decisions]].
