# Goal

Конкретный ожидаемый результат. Источник задачи и границы разрешённой работы.

# Current State

Ссылка на [[Project State]], тематические документы и проверенный текущий путь кода.

# Files / Systems Affected

Конкретные файлы, компоненты, сообщения и поля. Что зависит от изменения.

# Invariants That Must Not Break

Применимые [[Инварианты движка]] и контракты задачи.

# Implementation Steps

Небольшие проверяемые шаги. Не начинать без разрешённой задачи на реализацию.

# Validation

Поведенческие проверки и критерии приёмки. Отделять план проверки от фактического результата.

# Status

Template — не задача и не выполненный план. При создании рабочего плана использовать Draft, Planned, In progress или Complete и перечислить незавершённое.
