# Игровой движок

[[Точки входа]] · [[Состояние игры]] · [[Карты и сценарии]] · [[Правила Base Game]]

Движок в `app/engine` работает без React и PySide6. UI просит выполнить действие, движок проверяет правила и меняет состояние.

| Файл | Назначение |
| --- | --- |
| [state.py](../../app/engine/state.py) | Dataclass-модели, ресурсы, стоимости |
| [rules.py](../../app/engine/rules.py) | Создание партии и игровые операции |
| [maps.py](../../app/engine/maps.py) | Проверка и материализация JSON-карты |
| [board_geom.py](../../app/engine/board_geom.py) | Граф поля из геометрии гексов |
| [serialize.py](../../app/engine/serialize.py) | Преобразование состояния в JSON и обратно |
| __init__.py | Публичный импорт API |

## build_game

Принимает seed, max_players, size, необязательные имена и источник карты: map_id, map_path или map_data. Строит BoardState, создаёт игроков, настраивает snake order и перемешивает development deck. Возвращает GameState.

Game / Room UX 2.2, verified 2026-10-06: optional `starting_pid=0` передаётся make_setup_order, который строит rotated forward + reverse. Последняя setup road переводит main к setup_order[0], а не hardcoded 0. Сервер выбирает starter Random/Host; offline default остаётся прежним. Target VP override применяет server к уже существующему RulesConfig. Dice bag/timer/settings/chat/colors находятся в Room, движок получает прежние суммы roll/end commands. Никакие другие rules/dev/map branches этим этапом не менялись. 234 pytest; до/после scenarios 348/508 с одинаковыми 160 failures.

## apply_cmd

Принимает `g`, `pid`, словарь команды. Выбирает ветку по `cmd.type`, проверяет условия и меняет переданный объект g. Возвращает `(g, events)`; при нарушении правил поднимает RuleError с code/message/details.

| Действие | Где читать дальше |
| --- | --- |
| Поселение | apply_cmd → place_settlement → can_place_settlement |
| Дорога | apply_cmd → place_road → can_place_road |
| Город | apply_cmd → upgrade_city → can_upgrade_city |
| Кубики | apply_cmd → roll → distribute_for_roll |
| Банк | apply_cmd → trade_bank → trade_with_bank |
| Карты развития | buy_dev / play_dev |
| Достижения | longest_road_length, update_longest_road, update_largest_army |
| Победа | check_win |
| Море | build_ship, move_ship, move_pirate, choose_gold |

`events` — список описаний результата, например roll или place_road. Это не очередь React-событий. Сетевой сервер обновляет интерфейс снимками.

Проверено 2026-10-02: Phase 1 добавила строгие `_integer/_vertex/_edge/_tile`, отделила server-authoritative dice от trusted deterministic engine API и перенесла подтверждённые dev/fixture validations перед mutation. Year of Plenty агрегирует совпавшие ресурсы; public grant закрыт на server boundary. `serialize.to_player_dict` создаёт network projection; `to_dict/from_dict` не стали player-specific. Гарантии и пределы — [[Инварианты движка]]; regression evidence — [[Результаты аудита]].

> [!note] Чтение правил
> Имена функций показывают намерение, но не гарантируют выполнение всех требований. Сравнивай ветку команды с [[Инварианты движка]] и [[Результаты аудита]].
