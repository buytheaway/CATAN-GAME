## Trusted fog foundation — S2B-2B.1

Public availability **DISABLED**, implemented 2026-10-09. [exploration.py](../../app/engine/exploration.py) validates explicit profile, assignment digest, mask/ledger/continuation and same-match transitions; visible-only initial helpers reuse stored adjacency. `build_game(..., fog_rng=...)` is a trusted constructor for recipe v2/internal fixtures. ## Largest Army — focused correctness fix

`apply_cmd(play_dev)` → `play_dev` validates/consumes the mature Knight and increments `knights_played` → `update_largest_army` chooses the existing holder when it remains a qualified tied leader, otherwise a unique stronger leader → existing `check_win` considers only the active player. A retained/growing holder receives no additional VP; a transfer subtracts 2 from the previous owner and adds 2 to the new one once. Minimum three Knights and robber/pirate pending behavior remain.

Only `update_largest_army` changed. Snapshot decode/Room recovery never call this calculation or repair historical scores. Base/Seafarers, scenario-ledger preservation, frozen codecs and PostgreSQL recovery/receipt tests — [[Project State#Largest Army tie handling — focused correctness fix]].

## Seafarers core — S1, 2026-10-08

[rules.py](../../app/engine/rules.py) remains the single executor. `longest_road_length` retains its public name but adds ships only under enable_seafarers: DFS chooses one edge trail, never reuses an edge, permits vertex revisits in loops, requires own settlement/city for a change of piece kind and stops on arrival at foreign buildings. `update_longest_road` retains an eligible tied incumbent, transfers/removes exactly 2VP and is idempotent. `check_win` tests the active player; End Turn checks the new player before Roll. These last two are explicit corrections to shared intended Base rules, not Seafarers-only rewards.

`can_place_ship` requires an own building or own ship at an unblocked joint; roads alone do not anchor ships. Optional setup anchor/source exclusion serve the existing executor. `build_ship` supports setup and shared free-road credits; `_finish_setup_route` advances the same snake step for either piece. `can_place_settlement` accepts incident own ships only in Seafarers, retaining land, distance, payment and supply checks.

[shipping.py](../../app/engine/shipping.py) answers only maritime topology: own ships on a simple line between distinct own buildings are closed; foreign interruption does not reopen them. Ordinary free ends and official circle exceptions are checked separately. `move_ship` validates turn/Roll/pending, source ownership/age/one-move entitlement, source/target pirate, open topology and target placement excluding the source before any mutation. It scores only the final board.

`_collect_gold_yields` ignores robber-blocked Gold; `_begin_gold_choice`/`_advance_gold_choice` retain numeric recipient order and clear requests when no bank card remains. Second setup Gold resolves through existing choose_gold before the anchored route; setup index/anchor remain intact. No resource is auto-selected. State/history and verification — [[Состояние игры#Seafarers turn history — codec v2]], [[plans/seafarers-s1]].

## build_game

Принимает seed, max_players, size, необязательные имена и источник карты: map_id, map_path или map_data. Строит BoardState, создаёт игроков, настраивает snake order и перемешивает development deck. Возвращает GameState.

Game / Room UX 2.2, historical verification 2026-10-06: optional `starting_pid=0` передаётся make_setup_order, который строит rotated forward + reverse. Последний setup route переводит main к setup_order[0], а не hardcoded 0; после S1 это road или разрешённый anchored ship. Сервер выбирает starter Random/Host; offline default остаётся прежним. Target VP override применяет server к уже существующему RulesConfig. Dice bag/timer/settings/chat/colors находятся в Room, движок получает суммы roll/end commands. 234 pytest и 348/508 scenarios — результаты именно UX 2.2; текущая проверка — [[Project State]].

## apply_cmd

Принимает `g`, `pid`, словарь команды. Выбирает ветку по `cmd.type`, проверяет условия и меняет переданный объект g. Возвращает `(g, events)`; при нарушении правил поднимает RuleError с code/message/details.

| Действие | Где читать дальше |
| --- | --- |
| Поселение | apply_cmd: ветка `ctype == "place_settlement"` → can_place_settlement |
| Дорога | apply_cmd: ветка `ctype == "place_road"` → can_place_road |
| Город | apply_cmd: ветка `ctype == "upgrade_city"` → can_upgrade_city |
| Кубики | apply_cmd: ветка `ctype == "roll"` → distribute_for_roll |
| Банк | apply_cmd: ветка `ctype == "trade_bank"` → trade_with_bank |
| Карты развития | buy_dev / play_dev |
| Достижения | longest_road_length, update_longest_road, update_largest_army |
| Победа | check_win |
| Море | build_ship, move_ship, move_pirate, choose_gold |

`place_settlement`, `place_road`, `upgrade_city`, `roll` и морские имена в таблице — значения cmd.type и ветки apply_cmd, не отдельные одноимённые функции. Геометрические helpers can_place_* сами по себе не доказывают доступность действия: полную проверку ресурсов/supply/turn/lifecycle выполняет dispatcher. board_legal_moves использует этот же executor на копиях.

В multiplayer путь до этой функции: websocket_endpoint → protocol validation → _dispatch (account session) → _dispatch_impl → room.lock → ownership/ruleset/epoch/sequence checks → clone_room → server._apply_cmd(candidate) → engine.apply_cmd. Успех ещё не означает publication: `_commit` → Coordinator.commit → Repository.save → PostgreSQL COMMIT → `_promote` → F1-authorized personal snapshot → ACK. При final refusal domain candidate отбрасывается, сохраняются только consumed seq/receipt. В RAM-only dev DB шага нет; durable mode не делает fallback. Полный маршрут — [[Сценарий сетевой партии]].

`events` — список описаний результата, например roll или place_road. Это не очередь React-событий. Сетевой сервер обновляет интерфейс снимками.

Проверено 2026-10-02: Phase 1 добавила строгие `_integer/_vertex/_edge/_tile`, отделила server-authoritative dice от trusted deterministic engine API и перенесла подтверждённые dev/fixture validations перед mutation. Year of Plenty агрегирует совпавшие ресурсы; public grant закрыт на server boundary. `serialize.to_player_dict` создаёт network projection; `to_dict/from_dict` не стали player-specific.
