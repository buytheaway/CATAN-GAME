# Сценарий сетевой партии

[[Web клиент]] · [[Сервер и протокол]] · [[Игровой движок]]

Для чтения возьми два браузерных клиента с разными именами, новую комнату на два места и карту base_standard. Между стартом матча и броском обязательно проходит начальная расстановка.

## От запуска до матча

| Шаг | Файл и функция | Кто вызывает | Вход | Возврат / изменение |
| --- | --- | --- | --- | --- |
| 1. Запуск backend | app/server_mp.py: main | Python / RUN_SERVER | CATAN_HOST, CATAN_PORT | Uvicorn обслуживает FastAPI app |
| 2. Открытие web | web/src/main.tsx | script из index.html | #root | Создаёт App |
| 3. Исходный экран | App | React | match=null | Показывает LobbyPage |
| 4. Host | LobbyPage.onHost | Кнопка Host | Имя, URL, maxPlayers=2 | Вызывает client.host/connect |
| 5. Соединение | WSClient.openSocket / onopen | connect, затем браузер | URL, сохранённое намерение | WebSocket; hello и create_room |
| 6. Комната | websocket_endpoint → manager.create_room | FastAPI, ветка create_room | Имя, число мест | Создаёт Room; связывает ClientConn с pid=0; отправляет room_state и токен |
| 7. Лобби host | WSClient.handleMessage → App.onRoomState | onmessage | room_state JSON | setRoom; LobbyPage показывает участников |
| 8. Второй игрок | LobbyPage.onJoin → WSClient.join/connect | Кнопка Join второго браузера | Имя и room_code | Отправляет join_room |
| 9. Вход | websocket_endpoint → manager.join_room | Ветка join_room | Код и имя | Занимает слот; связывает соединение; рассылает room_state |
| 10. Старт | LobbyPage → WSClient.startMatch | Кнопка Start Match host | — | Сообщение start_match |
| 11. Создание партии | websocket_endpoint → _start_and_notify → _start_match | Ветка start_match | Room | Подключённый состав, компактные pid; новый match_id/internal seed; build_game; независимая колода; room.game; status=in_match |
| 12. Показ игры | _send_match_state → handleMessage → App | Серверная рассылка и onmessage | MatchState | setMatch; оба App показывают GamePage |

## Расстановка и бросок

| Шаг | Файл и функция | Кто вызывает | Вход | Возврат / изменение |
| --- | --- | --- | --- | --- |
| 13. Инструмент | BoardView.onSelectAction → GamePage.setSelectedAction | Кнопка Settlement/Road | Строка действия | Локальный selectedAction |
| 14. Место | BoardView.handleVertexClick / handleEdgeClick | Клик по подсветке | vid либо a,b | Команда place_settlement/place_road с setup=true |
| 15. Расстановка | WSClient.sendCmd → сервер → apply_cmd | Сетевой обработчик | g, pid, cmd | occupied_*; setup_need/index; после всех пар phase=main |
| 16. Roll | GamePage inline onClick | Кнопка Roll | `{type: "roll"}` | Вызывает WSClient.sendCmd |
| 17. Конверт | wsClient.ts: sendCmd | GamePage | Команда | Увеличивает seq; создаёт cmd_id; сохраняет pendingCmds; отправляет JSON |
| 18. Проверка | server_mp.websocket_endpoint | FastAPI после receive_text | JSON, ClientConn | Проверяет протокол, room, match_id, seq, pid |
| 19. Исполнение | server_mp._apply_cmd → _roll_dice → engine.rules.apply_cmd | Endpoint | Room, pid, только roll intent | Сервер генерирует две кости; движок меняет last_roll, rolled, roll_history |
| 20. Ресурсы | rules.distribute_for_roll | Ветка roll при результате не 7 | g, сумма кубиков | Переносит ресурсы из bank в PlayerState.res |
| 21. Рассылка | _send_match_state → _snapshot_state → _send | Endpoint после успеха | Room, game, pid каждого получателя | to_player_dict + you_pid/legal; увеличенный room.tick; персональный match_state каждому владельцу слота |
| 22. Второй клиент | WSClient.handleMessage | WebSocket.onmessage | Новый match_state | Сохраняет snapshot, вызывает onMatchState |
| 23. Перерисовка | App.setMatch → GamePage → BoardView | Callback, затем React | Новые props | Видимые ресурсы, статус, доступность кнопок |

При 7 шаг выдачи ресурсов заменяется pending discard/robber_move. При золоте появляется choose_gold. Это другой путь внутри той же команды, см. [[Правила Base Game]] и [[Правила Seafarers]].

> [!important] Проверено 2026-10-02
> Production WS принимает только roll intention; поля результата отклоняются. Отказ получает error и ACK applied=false и расходует transport seq, но не game/tick. Персональные snapshots различаются скрытой информацией; публичное поле/tick совпадает. Regression tests — [[Результаты аудита]].

## Маршрут чтения в IDE

`GamePage.tsx` → `sendCmd` в `wsClient.ts` → ветка cmd в `server_mp.py` → `_apply_cmd/_roll_dice` → ветка roll в `engine/rules.py` → `distribute_for_roll` → `_send_match_state` → `serialize.to_player_dict` → `WSClient.handleMessage` → callbacks в `App.tsx`.
