# Сценарий сетевой партии

[[Web клиент]] · [[Сервер и протокол]] · [[Игровой движок]]

Маршрут сверен с текущим кодом **2026-10-09, после S1/F1/F2/F3**. Для чтения возьми два guest-браузера с разными именами, новую комнату на два места и base_standard. Между стартом и Roll проходит setup; бросает текущий игрок из snapshot. Account Host/Join отличается проверкой cookie session, но использует тот же Room/engine/commit путь.

При 7 шаг выдачи ресурсов заменяется pending discard/robber_move. При золоте появляется choose_gold. Это другой путь внутри той же команды, см. [[Правила Base Game]] и [[Правила Seafarers]].

> [!important] Границы авторитетности и отказа
> Кнопки и legal hints не заменяют backend validation. Final sequential command refusal получает error/ACK applied=false и расходует только transport seq; protocol/ownership/compatibility/epoch/gap checks до executor не обещают ACK и не расходуют seq. В durable mode COMMIT обязателен перед успехом/publication; при DB failure нет RAM fallback. RAM-only dev использует тот же candidate/executor путь без PostgreSQL.

F2 legacy Continue сохраняет authentication/seat, но показывает compatibility notice без игрового snapshot, timer actions и rematch; новая игра создаётся в отдельной комнате. Нормальная recovery не запускает правила, не пересчитывает VP/achievements и не генерирует карту. F1 publication authorization остаётся отдельным последним барьером даже для уже открытого WS. Подробности — [[Сервер и протокол]], [[Architecture Decisions]].

Историческая проверка Phase 1 — 2026-10-02; последняя полная Python verification после F3 — **757 passed/0 skipped**, web после F2 — **241 passed**. Текущие даты, focused browser acceptance и ограничения — [[Project State]]. Это маршрут чтения кода, не заявление о новой полной browser-партии.

## Маршрут чтения в IDE

Roll: `GamePage.tsx` → `game/useGameCommand.ts: submit` → `WSClient.sendCmd` → `server_mp.websocket_endpoint/_dispatch/_dispatch_impl` → `clone_room/_apply_cmd` → `engine.rules.apply_cmd/distribute_for_roll` → `persistence/coordinator.py: commit` → `repositories.py: save/COMMIT` → `_promote/_send_match_state/_snapshot_state` → `serialize.to_player_dict` и `engine.legal.board_legal_moves` → `match_state_message/_publish_match_state` → `WSClient.handleMessage` → `App.onMatchState` → HUD/BoardRenderer.

Board click: сначала `board/useBoardInteraction.ts` → `board/interaction.ts: createBoardInteraction`, затем тот же sendCmd/dispatch/commit путь. Имена `place_settlement/place_road/upgrade_city` обозначают ветки apply_cmd, а не отдельные функции. `_start_and_notify` остаётся helper для других вызовов; production WS start проходит через _dispatch_impl.
